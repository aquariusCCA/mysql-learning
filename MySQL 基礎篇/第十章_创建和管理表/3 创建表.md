# 3 創建表

返回章節：[第十章_创建和管理表](./README.md)

## 本節導讀

這一節正式進入「定義資料表」的核心操作。

前面兩篇已經建立了共同背景：

```text
資料庫伺服器
    ↓
資料庫 database
    ↓
資料表 table
    ↓
欄位 column / 資料列 row
```

到了這一篇，重點會落在：**如何把一個業務對象設計成一張真正可以儲存資料的 MySQL 表。**

例如「使用者」這個業務對象，進入 MySQL 之前，你不能只想著「我要建一張 user 表」，而是要先拆成一組欄位：

```text
使用者
├── id
├── username
├── email
├── status
├── balance
├── created_at
└── updated_at
```

接著再為每個欄位決定：

- 欄位名稱叫什麼；
- 使用什麼資料型別；
- 能不能為 `NULL`；
- 是否要有預設值；
- 是否要作為主鍵；
- 是否要唯一；
- 是否需要自動遞增；
- 是否需要索引、註解、字元集或其他限制。

所以，`CREATE TABLE` 不是單純背語法，而是在回答這個問題：

> 這份資料未來要怎麼被安全、穩定、可維護地存進資料庫？

這一篇學完後，你應該要能做到：**看懂一段建表語句、自己寫出基本建表語句，並且知道 `CREATE TABLE`、`CREATE TABLE ... LIKE`、`CREATE TABLE ... AS SELECT` 分別適合什麼場景。**

## 關鍵字

- 主題：創建表、建立資料表、欄位定義、主鍵、自增、預設值、約束、複製表結構、查詢結果建表、查看表結構
- 英文：create table, column definition, primary key, auto increment, default value, constraint, create table like, create table as select, CTAS, describe table, show columns, show create table
- 常見搜尋：MySQL 建表語法、MySQL create table、MySQL 主鍵自增、MySQL 複製表結構、MySQL 根據查詢結果建表、MySQL DESC、MySQL SHOW CREATE TABLE
- 容易混淆：`CREATE DATABASE` vs `CREATE TABLE`、`CREATE TABLE ... LIKE` vs `CREATE TABLE ... AS SELECT`、`DESC` vs `SHOW CREATE TABLE`、資料型別長度 vs 顯示寬度、`DOUBLE` vs `DECIMAL`

## 建議回查情境

- 準備建立一張新表，但忘了 `CREATE TABLE` 的基本骨架時。
- 不確定欄位定義中哪些是必要資訊、哪些是可選資訊時。
- 不知道主鍵、自增、唯一、預設值應該寫在哪裡時。
- 想快速複製一張表的結構，但不想複製資料時。
- 想把某個查詢結果直接變成一張新表時。
- 建表後想確認實際欄位、索引、引擎、字元集與完整 SQL 時。

## 30 秒複習入口

- `CREATE TABLE` 的核心是：**表名 + 欄位定義 + 約束 + 表選項**。
- 最推薦的日常建表方式是「直接定義欄位」，因為你可以明確控制型別、主鍵、索引、預設值與註解。
- `CREATE TABLE ... LIKE 原表` 適合快速複製「表結構」，通常會保留欄位屬性與索引，但不複製資料。
- `CREATE TABLE ... AS SELECT ...` 適合把「查詢結果」快速轉成新表，但它不是完整複製原表結構。
- `CREATE TABLE 新表 AS SELECT * FROM 原表 WHERE 1=2;` 可以建立沒有資料的新表，但它不等於 `LIKE`，因為索引、自增等資訊可能不會完整保留。
- `DESC 表名;` / `DESCRIBE 表名;` 適合快速看欄位。
- `SHOW FULL COLUMNS FROM 表名;` 可以看到欄位 collation、comment、權限等更多資訊。
- `SHOW CREATE TABLE 表名\G` 適合查看完整建表語句，包含主鍵、索引、約束、引擎、字元集、排序規則等。
- MySQL 8.x 中，不建議再依賴 `INT(11)`、`INT(2)` 這類整數顯示寬度寫法。
- 金額、利率、財務數字應優先使用 `DECIMAL(M,D)`，不要用 `DOUBLE` 當作精確金額欄位。

## 速查區

### 最常用建表骨架

```sql
CREATE TABLE IF NOT EXISTS table_name (
    column_name data_type [column_options],
    column_name data_type [column_options],
    [table_constraints]
) ENGINE = InnoDB
  DEFAULT CHARSET = utf8mb4
  COLLATE = utf8mb4_0900_ai_ci
  COMMENT = 'table comment';
```

最重要的四層是：

| 層級 | 代表內容 | 範例 |
| --- | --- | --- |
| 表名 | 這張表叫什麼 | `app_user` |
| 欄位 | 表裡有哪些資料欄位 | `id`, `username`, `created_at` |
| 欄位規則 | 型別、是否可空、預設值、自增、註解 | `BIGINT NOT NULL AUTO_INCREMENT` |
| 表級規則 | 主鍵、唯一索引、檢查約束、外鍵等 | `PRIMARY KEY (id)` |

### 一張表的推薦起手範例

```sql
CREATE TABLE IF NOT EXISTS app_user (
    id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '使用者ID',
    username VARCHAR(50) NOT NULL COMMENT '帳號',
    email VARCHAR(100) NOT NULL COMMENT '電子信箱',
    status TINYINT NOT NULL DEFAULT 1 COMMENT '狀態：1啟用，0停用',
    balance DECIMAL(12, 2) NOT NULL DEFAULT 0.00 COMMENT '帳戶餘額',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '建立時間',
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新時間',

    PRIMARY KEY (id),
    UNIQUE KEY uk_app_user_username (username),
    UNIQUE KEY uk_app_user_email (email),
    CHECK (status IN (0, 1))
) ENGINE = InnoDB
  DEFAULT CHARSET = utf8mb4
  COLLATE = utf8mb4_0900_ai_ci
  COMMENT = '使用者表';
```

這段建表語句可以拆成：

| 部分 | 說明 |
| --- | --- |
| `id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT` | 使用者主鍵，自動遞增，不允許空值 |
| `username VARCHAR(50) NOT NULL` | 帳號，最多 50 個字元，不允許空值 |
| `email VARCHAR(100) NOT NULL` | 電子信箱，不允許空值 |
| `status TINYINT NOT NULL DEFAULT 1` | 狀態欄位，預設啟用 |
| `balance DECIMAL(12,2)` | 精確小數，適合金額 |
| `created_at` | 建立時間，預設目前時間 |
| `updated_at` | 更新時間，資料更新時自動更新 |
| `PRIMARY KEY (id)` | 指定主鍵 |
| `UNIQUE KEY ...` | 指定唯一索引，避免帳號或 email 重複 |
| `CHECK (status IN (0, 1))` | 限制狀態只能是 0 或 1 |
| `ENGINE = InnoDB` | 使用 InnoDB 儲存引擎 |
| `DEFAULT CHARSET = utf8mb4` | 使用 `utf8mb4` 字元集 |

> 補充：如果你所在環境是 MySQL 5.7 或較舊版本，`utf8mb4_0900_ai_ci` 可能不存在，需改用該版本支援的 collation，例如 `utf8mb4_unicode_ci`。

### 三種常見建表方式比較

| 建表方式 | 語法 | 是否複製資料 | 是否適合正式表設計 | 主要用途 |
| --- | --- | --- | --- | --- |
| 直接定義欄位 | `CREATE TABLE t (...)` | 否 | 適合 | 正式建表、明確設計欄位與約束 |
| 複製表結構 | `CREATE TABLE new_t LIKE old_t` | 否 | 視情況 | 快速建立同結構空表 |
| 查詢結果建表 | `CREATE TABLE new_t AS SELECT ...` | 通常會 | 不建議當正式表設計主方式 | 快速保存查詢結果、臨時分析、資料轉存 |

### 建完表後的檢查命令

| 目的 | 語法 | 適合看什麼 |
| --- | --- | --- |
| 快速看欄位 | `DESC 表名;` | 欄位名、型別、是否可空、Key、預設值、Extra |
| 快速看欄位 | `DESCRIBE 表名;` | 與 `DESC` 類似 |
| 看更多欄位資訊 | `SHOW FULL COLUMNS FROM 表名;` | 欄位 collation、comment、權限等 |
| 看完整建表 SQL | `SHOW CREATE TABLE 表名\G` | 主鍵、索引、約束、引擎、字元集、排序規則、註解 |

### 高風險與易錯提醒

```sql
CREATE TABLE emp (
    emp_id INT,
    salary DOUBLE
);
```

上面這種寫法能跑，但不夠適合實務，原因是：

- `emp_id` 沒有主鍵，後續資料識別會不穩定；
- `salary DOUBLE` 是近似值，不適合薪資、金額、利率；
- 沒有 `NOT NULL`、`DEFAULT`、`COMMENT`，可讀性和約束力不足；
- 沒指定表的字元集與排序規則時，會依照資料庫或伺服器預設值決定。

較好的方向是：

```sql
CREATE TABLE emp (
    emp_id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '員工ID',
    emp_name VARCHAR(50) NOT NULL COMMENT '員工姓名',
    salary DECIMAL(12, 2) NOT NULL DEFAULT 0.00 COMMENT '月薪',
    birthday DATE NULL COMMENT '生日',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '建立時間',

    PRIMARY KEY (emp_id)
) ENGINE = InnoDB
  DEFAULT CHARSET = utf8mb4
  COLLATE = utf8mb4_0900_ai_ci
  COMMENT = '員工表';
```

## 3.1 建表前先想清楚的 6 件事

正式寫 `CREATE TABLE` 前，建議先問自己這 6 個問題：

### 1. 這張表屬於哪個資料庫？

先確認目前使用中的資料庫：

```sql
SELECT DATABASE();
```

如果結果是 `NULL`，代表還沒有選擇預設資料庫，需要先切換：

```sql
USE shop_db;
```

或直接使用完整名稱：

```sql
CREATE TABLE shop_db.app_user (...);
```

### 2. 這張表代表什麼業務對象？

一張表最好代表一種清楚的業務對象，例如：

| 業務對象 | 建議表名 |
| --- | --- |
| 使用者 | `app_user` |
| 訂單 | `user_order` |
| 訂單明細 | `order_item` |
| 商品 | `product` |
| 部門 | `department` |
| 員工 | `employee` |

不要把太多不相關的資料硬塞在同一張表裡。

### 3. 每個欄位存什麼資料？

例如使用者表：

| 欄位 | 存放內容 |
| --- | --- |
| `id` | 使用者唯一識別 |
| `username` | 登入帳號 |
| `email` | 電子信箱 |
| `status` | 啟用 / 停用狀態 |
| `created_at` | 建立時間 |
| `updated_at` | 更新時間 |

欄位不是越多越好，而是要能清楚描述這張表的業務資料。

### 4. 每個欄位應該用什麼資料型別？

常見選擇方向：

| 資料 | 建議型別 | 說明 |
| --- | --- | --- |
| 主鍵 ID | `BIGINT UNSIGNED` | 比 `INT` 更有成長空間 |
| 狀態碼 | `TINYINT` | 例如 0/1、1/2/3 |
| 姓名、帳號 | `VARCHAR(n)` | 長度不固定的字串 |
| 金額、利率 | `DECIMAL(M,D)` | 精確小數 |
| 日期 | `DATE` | 只存年月日 |
| 日期時間 | `DATETIME` | 存年月日時分秒 |
| 長文章 | `TEXT` / `MEDIUMTEXT` / `LONGTEXT` | 依內容大小選擇 |
| 圖片、檔案二進位 | `BLOB` 類型 | 但實務上常改存檔案路徑或物件儲存 URL |

### 5. 哪些欄位不能為空？

例如：

```sql
username VARCHAR(50) NOT NULL
```

代表 `username` 必須有值。

如果欄位可以暫時沒有資料，可以寫成：

```sql
birthday DATE NULL
```

實務建議：

- 主鍵通常 `NOT NULL`；
- 帳號、訂單編號、建立時間通常 `NOT NULL`；
- 備註、生日、第二電話等可選資料可以允許 `NULL`；
- 不要所有欄位都無腦允許 `NULL`，否則後續查詢與統計會變得麻煩。

### 6. 哪些規則應該由資料庫保護？

例如：

| 規則 | SQL 寫法 |
| --- | --- |
| 每筆資料要有唯一 ID | `PRIMARY KEY (id)` |
| 帳號不能重複 | `UNIQUE KEY uk_user_username (username)` |
| 狀態要有預設值 | `status TINYINT NOT NULL DEFAULT 1` |
| 金額不能為空 | `amount DECIMAL(12,2) NOT NULL DEFAULT 0.00` |
| 狀態只能是特定值 | `CHECK (status IN (0, 1))` |

資料庫約束不是用來取代程式驗證，而是最後一道防線。

## 3.2 創建方式一：直接定義欄位

這是最重要、也最推薦掌握的建表方式。

### 3.2.1 基本語法

```sql
CREATE TABLE [IF NOT EXISTS] 表名 (
    欄位名 資料型別 [欄位選項],
    欄位名 資料型別 [欄位選項],
    ...
    [表級約束]
) [表選項];
```

可以拆成：

```text
CREATE TABLE        建立資料表
IF NOT EXISTS       如果表不存在才建立
表名                這張表的名稱
欄位名              這張表有哪些欄位
資料型別            每個欄位能存什麼資料
欄位選項            NOT NULL、DEFAULT、AUTO_INCREMENT、COMMENT 等
表級約束            PRIMARY KEY、UNIQUE KEY、CHECK、FOREIGN KEY 等
表選項              ENGINE、CHARSET、COLLATE、COMMENT 等
```

### 3.2.2 欄位定義的基本骨架

```sql
欄位名 資料型別 [NULL | NOT NULL] [DEFAULT 預設值] [AUTO_INCREMENT] [COMMENT '註解']
```

例如：

```sql
username VARCHAR(50) NOT NULL COMMENT '帳號'
```

意思是：

- 欄位名稱：`username`
- 資料型別：`VARCHAR(50)`
- 是否可空：`NOT NULL`
- 欄位註解：`帳號`

再例如：

```sql
status TINYINT NOT NULL DEFAULT 1 COMMENT '狀態：1啟用，0停用'
```

意思是：

- `status` 存小整數；
- 不允許 `NULL`；
- 如果新增資料時沒有指定值，預設是 `1`；
- 註解說明 1 和 0 的業務意義。

### 3.2.3 表級約束常見寫法

```sql
PRIMARY KEY (id)
```

代表 `id` 是主鍵。

```sql
UNIQUE KEY uk_app_user_username (username)
```

代表 `username` 不能重複。

```sql
KEY idx_app_user_status (status)
```

代表替 `status` 建立普通索引，方便依狀態查詢。

```sql
CHECK (status IN (0, 1))
```

代表 `status` 只能符合指定條件。

```sql
CONSTRAINT fk_order_user
    FOREIGN KEY (user_id) REFERENCES app_user(id)
```

代表 `user_order.user_id` 必須對應到 `app_user.id`。

> 這一篇先掌握寫法與用途即可；主鍵、唯一、索引、外鍵的設計原則可以放到後續章節再深入。

### 3.2.4 完整例子：部門表

```sql
CREATE TABLE IF NOT EXISTS department (
    dept_id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '部門ID',
    dept_name VARCHAR(50) NOT NULL COMMENT '部門名稱',
    location VARCHAR(100) NULL COMMENT '部門位置',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '建立時間',

    PRIMARY KEY (dept_id),
    UNIQUE KEY uk_department_dept_name (dept_name)
) ENGINE = InnoDB
  DEFAULT CHARSET = utf8mb4
  COLLATE = utf8mb4_0900_ai_ci
  COMMENT = '部門表';
```

這個例子比傳統教材中的下面寫法更適合實務：

```sql
CREATE TABLE dept(
    deptno INT(2) AUTO_INCREMENT,
    dname VARCHAR(14),
    loc VARCHAR(13),
    PRIMARY KEY (deptno)
);
```

原因是：

- `INT(2)` 的 `2` 是顯示寬度概念，不代表只能存兩位數；MySQL 8.x 已不建議依賴整數顯示寬度。
- 欄位名 `dept_id`、`dept_name` 比 `deptno`、`dname` 更容易理解。
- 使用 `COMMENT` 可以讓表結構自帶說明。
- 明確指定 `ENGINE`、`CHARSET`、`COLLATE`，可讀性更好。
- `created_at` 是實務常見欄位，方便追蹤資料建立時間。

### 3.2.5 完整例子：員工表

```sql
CREATE TABLE IF NOT EXISTS employee (
    emp_id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '員工ID',
    emp_name VARCHAR(50) NOT NULL COMMENT '員工姓名',
    dept_id BIGINT UNSIGNED NULL COMMENT '所屬部門ID',
    salary DECIMAL(12, 2) NOT NULL DEFAULT 0.00 COMMENT '月薪',
    birthday DATE NULL COMMENT '生日',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '建立時間',
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新時間',

    PRIMARY KEY (emp_id),
    KEY idx_employee_dept_id (dept_id),
    CONSTRAINT fk_employee_department
        FOREIGN KEY (dept_id) REFERENCES department(dept_id)
) ENGINE = InnoDB
  DEFAULT CHARSET = utf8mb4
  COLLATE = utf8mb4_0900_ai_ci
  COMMENT = '員工表';
```

這裡特別注意兩點：

1. `salary` 使用 `DECIMAL(12, 2)`，不要用 `DOUBLE` 當作精確薪資。
2. `dept_id` 如果要建立外鍵，資料型別必須和被參照的 `department.dept_id` 相容。

## 3.3 `IF NOT EXISTS` 的作用與限制

```sql
CREATE TABLE IF NOT EXISTS app_user (...);
```

這句的意思是：

- 如果 `app_user` 不存在，就建立它；
- 如果 `app_user` 已存在，就不要報錯，也不要重新建立。

這很適合練習腳本、初始化腳本、重複執行的 demo SQL。

但是要注意：

> `IF NOT EXISTS` 只避免「表已存在」造成錯誤，不會幫你檢查既有表的結構是否符合目前腳本。

例如，你寫：

```sql
CREATE TABLE IF NOT EXISTS app_user (
    id BIGINT PRIMARY KEY,
    username VARCHAR(50) NOT NULL
);
```

如果資料庫裡已經有一張舊的 `app_user`，但舊表沒有 `username` 欄位，這句 SQL 仍然不會幫你改表。

所以正式環境中，建表與改表應該搭配版本化 migration 工具或明確的 `ALTER TABLE` 腳本，而不是只依賴 `IF NOT EXISTS`。

## 3.4 創建方式二：`CREATE TABLE ... LIKE`

如果你想快速建立一張「結構類似原表，但沒有資料」的新表，可以使用：

```sql
CREATE TABLE new_app_user LIKE app_user;
```

這句的意思是：

> 根據 `app_user` 的表定義建立 `new_app_user`，但不複製資料。

### 3.4.1 使用場景

`LIKE` 適合：

- 建立測試用空表；
- 建立臨時備份結構；
- 建立同結構的分表或暫存表；
- 想保留欄位屬性與索引時。

例如：

```sql
CREATE TABLE app_user_2026 LIKE app_user;
```

接著可以手動插入需要的資料：

```sql
INSERT INTO app_user_2026
SELECT *
FROM app_user
WHERE created_at >= '2026-01-01';
```

### 3.4.2 `LIKE` 的注意點

`CREATE TABLE ... LIKE` 常被理解成「複製原表結構」，但仍要注意：

- 它不複製資料；
- 它只適用於 base table，不適用於 view；
- 它通常會保留欄位屬性與索引；
- 外鍵定義不一定會被保留；
- 如果原表是 `TEMPORARY`，新表不會自動變成 `TEMPORARY`，除非你明確寫 `CREATE TEMPORARY TABLE ... LIKE`。

所以，如果你要的是「完整資料備份」，不能只寫 `LIKE`。

## 3.5 創建方式三：`CREATE TABLE ... AS SELECT`

`CREATE TABLE ... AS SELECT` 通常簡稱 CTAS，用途是：

> 把一個查詢結果直接建立成新表。

基本語法：

```sql
CREATE TABLE 新表 AS
SELECT ...
FROM 原表
WHERE 條件;
```

也可以省略 `AS`：

```sql
CREATE TABLE 新表
SELECT ...
FROM 原表;
```

不過學習時建議保留 `AS`，可讀性比較好。

### 3.5.1 複製整張表的資料

```sql
CREATE TABLE employee_copy AS
SELECT *
FROM employee;
```

這會建立 `employee_copy`，並把查詢結果插入新表。

### 3.5.2 只建立空表

```sql
CREATE TABLE employee_empty AS
SELECT *
FROM employee
WHERE 1 = 2;
```

`WHERE 1 = 2` 永遠不成立，所以查不到資料。

因此結果是：

- 建立新表；
- 根據 `SELECT` 結果推導欄位；
- 不插入任何資料。

這種寫法常用於快速建立空表，但要記住：

> 它不是完整複製原表結構。

如果你的目標是複製表結構，通常優先考慮：

```sql
CREATE TABLE employee_empty LIKE employee;
```

### 3.5.3 建立查詢結果表

```sql
CREATE TABLE dept_salary_summary AS
SELECT
    dept_id,
    COUNT(*) AS employee_count,
    SUM(salary) AS total_salary,
    AVG(salary) AS avg_salary
FROM employee
GROUP BY dept_id;
```

這種寫法適合臨時分析、報表中間表、資料轉存。

務必替運算欄位取別名，例如：

```sql
COUNT(*) AS employee_count
SUM(salary) AS total_salary
AVG(salary) AS avg_salary
```

不要讓 MySQL 自動產生奇怪欄位名，例如 `COUNT(*)` 或 `salary * 12`。

### 3.5.4 可以搭配欄位定義

MySQL 也允許在 `CREATE TABLE` 部分先寫部分欄位或約束，再接 `SELECT`：

```sql
CREATE TABLE high_salary_employee (
    row_id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    PRIMARY KEY (row_id)
) AS
SELECT
    emp_id,
    emp_name,
    salary
FROM employee
WHERE salary >= 100000;
```

概念上可以理解成：

- `CREATE TABLE (...)` 裡定義的欄位會先出現；
- `SELECT` 查出來的欄位會接在後面；
- 如果有運算式，最好明確取別名；
- 如果要索引，應明確寫在 `CREATE TABLE` 部分。

### 3.5.5 CTAS 的重要限制

`CREATE TABLE ... AS SELECT` 很方便，但不能把它誤解為「完整複製原表」。

常見限制：

- 不會自動替你建立所有索引；
- `AUTO_INCREMENT` 等屬性可能不會保留；
- 生成欄位資訊可能不會保留；
- 部分資料型別可能因推導而和原表不同；
- 查詢中的運算式如果沒有別名，可能得到不理想的欄位名；
- 用來做正式表設計時，可維護性通常不如直接定義欄位。

所以可以這樣記：

```text
CREATE TABLE ... LIKE
    偏向複製表結構

CREATE TABLE ... AS SELECT
    偏向保存查詢結果
```

## 3.6 `LIKE` 與 `AS SELECT` 差異總整理

| 比較項目 | `CREATE TABLE new LIKE old` | `CREATE TABLE new AS SELECT ...` |
| --- | --- | --- |
| 核心目的 | 複製表結構 | 保存查詢結果 |
| 是否複製資料 | 不會 | 會，除非查詢結果為空 |
| 是否保留索引 | 通常會保留一般索引與主鍵 | 不會自動完整保留 |
| 是否保留自增 | 通常會保留欄位屬性 | 可能不保留 |
| 是否適合建立空同結構表 | 適合 | 可用，但不是最精準 |
| 是否適合建立報表中間表 | 不適合 | 適合 |
| 是否可根據多表查詢建表 | 不行 | 可以 |

### 情境選擇

如果你想要：

```text
我要一張和 employee 結構很像的空表
```

優先用：

```sql
CREATE TABLE employee_empty LIKE employee;
```

如果你想要：

```text
我要把 employee 中薪資大於 100000 的資料另存成新表
```

用：

```sql
CREATE TABLE high_salary_employee AS
SELECT *
FROM employee
WHERE salary > 100000;
```

如果你想要：

```text
我要把查詢統計結果存成一張表
```

用：

```sql
CREATE TABLE dept_salary_summary AS
SELECT
    dept_id,
    COUNT(*) AS employee_count,
    SUM(salary) AS total_salary
FROM employee
GROUP BY dept_id;
```

## 3.7 查看資料表結構

建完表後，一定要檢查實際結果。

因為你寫的 SQL 和 MySQL 最後保存下來的表定義，不一定完全長得一樣。MySQL 可能會規範化語法、補上預設值，或用標準格式顯示欄位資訊。

### 3.7.1 使用 `DESC` / `DESCRIBE`

```sql
DESC app_user;
```

或：

```sql
DESCRIBE app_user;
```

常見輸出欄位：

| 欄位 | 意義 |
| --- | --- |
| `Field` | 欄位名稱 |
| `Type` | 欄位資料型別 |
| `Null` | 是否允許 `NULL` |
| `Key` | 是否為主鍵、唯一索引、普通索引的一部分 |
| `Default` | 預設值 |
| `Extra` | 額外資訊，例如 `auto_increment`、`DEFAULT_GENERATED` |

適合快速確認：

- 欄位是否建立成功；
- 型別是否符合預期；
- 主鍵是否正確；
- 是否允許空值；
- 預設值是否正確。

### 3.7.2 使用 `SHOW COLUMNS`

```sql
SHOW COLUMNS FROM app_user;
```

它和 `DESC` 類似。

如果想看更多欄位資訊，可以用：

```sql
SHOW FULL COLUMNS FROM app_user;
```

`SHOW FULL COLUMNS` 可以看到：

- 欄位 collation；
- 欄位 comment；
- 欄位權限；
- 更完整的欄位資訊。

### 3.7.3 使用 `SHOW CREATE TABLE`

```sql
SHOW CREATE TABLE app_user\G
```

這是最重要的回查命令之一。

它可以看到完整建表語句，通常包含：

- 欄位定義；
- 主鍵；
- 唯一索引；
- 普通索引；
- `CHECK` 約束；
- 外鍵約束；
- 儲存引擎；
- 預設字元集；
- 排序規則；
- 表註解。

如果你想確認「這張表在 MySQL 裡真正長什麼樣」，優先看：

```sql
SHOW CREATE TABLE 表名\G
```

## 3.8 常見錯誤整理

### 錯誤 1：忘記選擇資料庫

```sql
CREATE TABLE app_user (...);
```

如果沒有先執行：

```sql
USE shop_db;
```

可能會出現 `No database selected`。

解法：

```sql
SELECT DATABASE();
USE shop_db;
```

或使用完整表名：

```sql
CREATE TABLE shop_db.app_user (...);
```

### 錯誤 2：把 `INT(11)` 理解成只能存 11 位數

```sql
id INT(11)
```

這裡的 `11` 是顯示寬度概念，不是數值範圍。

整數能存的範圍由型別本身決定，例如：

- `TINYINT`
- `SMALLINT`
- `INT`
- `BIGINT`

MySQL 8.x 中不建議新筆記再強調 `INT(11)` 這種寫法。

### 錯誤 3：金額使用 `FLOAT` / `DOUBLE`

```sql
salary DOUBLE
```

這不適合保存精確金額。

應改成：

```sql
salary DECIMAL(12, 2)
```

記法：

```text
FLOAT / DOUBLE：近似值，適合測量、科學計算
DECIMAL：精確值，適合金額、利率、財務數字
```

### 錯誤 4：以為 `AS SELECT WHERE 1=2` 等於完整複製表結構

```sql
CREATE TABLE employee_empty AS
SELECT *
FROM employee
WHERE 1 = 2;
```

這可以建立空表，但不是完整複製原表結構。

如果要複製結構，優先用：

```sql
CREATE TABLE employee_empty LIKE employee;
```

### 錯誤 5：運算欄位沒有取別名

```sql
CREATE TABLE dept_summary AS
SELECT dept_id, COUNT(*), SUM(salary)
FROM employee
GROUP BY dept_id;
```

不建議這樣寫，因為欄位名可能不好看。

建議改成：

```sql
CREATE TABLE dept_summary AS
SELECT
    dept_id,
    COUNT(*) AS employee_count,
    SUM(salary) AS total_salary
FROM employee
GROUP BY dept_id;
```

### 錯誤 6：建正式表時沒有主鍵

```sql
CREATE TABLE app_user (
    username VARCHAR(50),
    email VARCHAR(100)
);
```

正式業務表通常應該要有主鍵，例如：

```sql
CREATE TABLE app_user (
    id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    username VARCHAR(50) NOT NULL,
    email VARCHAR(100) NOT NULL,
    PRIMARY KEY (id)
);
```

## 3.9 本節實務判斷口訣

### 建正式業務表

優先使用：

```sql
CREATE TABLE 表名 (
    欄位定義,
    主鍵,
    必要索引,
    必要約束
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4;
```

重點是：

- 自己清楚定義欄位；
- 自己清楚定義主鍵；
- 自己清楚定義金額、日期、狀態等型別；
- 不要完全依賴查詢結果推導正式表結構。

### 建同結構空表

優先使用：

```sql
CREATE TABLE 新表 LIKE 原表;
```

### 建查詢結果表

使用：

```sql
CREATE TABLE 新表 AS
SELECT ...;
```

並記得：

- 運算欄位要取別名；
- 不要期待它完整保留原表索引與自增；
- 建完後用 `SHOW CREATE TABLE` 檢查。

### 檢查表結構

快速看欄位：

```sql
DESC 表名;
```

完整看建表 SQL：

```sql
SHOW CREATE TABLE 表名\G
```

## 3.10 最小完整練習

可以用下面這組 SQL 練習完整流程：

```sql
CREATE DATABASE IF NOT EXISTS demo_db
    DEFAULT CHARACTER SET utf8mb4
    DEFAULT COLLATE utf8mb4_0900_ai_ci;

USE demo_db;

CREATE TABLE IF NOT EXISTS product (
    product_id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '商品ID',
    product_name VARCHAR(100) NOT NULL COMMENT '商品名稱',
    price DECIMAL(12, 2) NOT NULL DEFAULT 0.00 COMMENT '售價',
    stock INT NOT NULL DEFAULT 0 COMMENT '庫存數量',
    status TINYINT NOT NULL DEFAULT 1 COMMENT '狀態：1上架，0下架',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '建立時間',
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新時間',

    PRIMARY KEY (product_id),
    KEY idx_product_status (status),
    CHECK (price >= 0),
    CHECK (stock >= 0),
    CHECK (status IN (0, 1))
) ENGINE = InnoDB
  DEFAULT CHARSET = utf8mb4
  COLLATE = utf8mb4_0900_ai_ci
  COMMENT = '商品表';

DESC product;
SHOW FULL COLUMNS FROM product;
SHOW CREATE TABLE product\G
```

接著練習複製空結構：

```sql
CREATE TABLE product_empty LIKE product;
SHOW CREATE TABLE product_empty\G
```

再練習查詢結果建表：

```sql
CREATE TABLE product_on_sale AS
SELECT
    product_id,
    product_name,
    price,
    stock
FROM product
WHERE status = 1;

SHOW CREATE TABLE product_on_sale\G
```

最後比較：

```sql
DESC product;
DESC product_empty;
DESC product_on_sale;
```

觀察三者的差異：

- `product`：正式設計表；
- `product_empty`：由 `LIKE` 複製出來的空結構表；
- `product_on_sale`：由查詢結果推導出來的新表。

## 3.11 本節總結

這一篇可以用三句話收束：

```text
正式建表：CREATE TABLE 表名 (...)
複製結構：CREATE TABLE 新表 LIKE 原表
保存查詢結果：CREATE TABLE 新表 AS SELECT ...
```

真正重要的不是背下語法，而是分清楚：

- 你是在設計正式業務表；
- 還是在複製既有表結構；
- 還是在保存某次查詢結果。

如果是正式業務表，請優先自己明確設計：

- 欄位名稱；
- 資料型別；
- `NULL` / `NOT NULL`；
- `DEFAULT`；
- 主鍵；
- 唯一約束；
- 必要索引；
- 表註解；
- 字元集與排序規則。

建完之後，不要只相信自己寫的 SQL，還要回頭檢查：

```sql
DESC 表名;
SHOW CREATE TABLE 表名\G
```

這樣才算真正完成建表。
