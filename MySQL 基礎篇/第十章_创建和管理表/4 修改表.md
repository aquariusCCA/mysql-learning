# 4 修改表

返回章節：[第十章_创建和管理表](./README.md)

## 本節導讀

這一節處理的是：**表已經建好了，後面還想調整表結構時，應該怎麼做。**

在真實專案中，資料表結構很少一次設計完就永遠不變。需求一變，表結構就可能跟著調整，例如：

- 使用者資料表要新增 `phone` 手機欄位；
- 商品資料表的 `price` 要從整數改成 `DECIMAL(12,2)`；
- 原本的 `name` 欄位想改成語意更清楚的 `username`；
- 某個舊欄位已經不再使用，需要刪除；
- 欄位預設值、是否可為 `NULL`、註解、位置需要調整；
- 需要新增或刪除索引、唯一約束、外鍵、檢查約束。

這些動作大多會使用：

```sql
ALTER TABLE 表名 ...;
```

不過，`ALTER TABLE` 不是普通查詢，它屬於 **DDL，Data Definition Language，資料定義語言**。它修改的是資料表結構，而不是單純修改某幾筆資料。

所以這一篇不只要背語法，還要建立一個很重要的觀念：

> 修改表結構前，要先確認影響範圍；正式環境中的 `ALTER TABLE` 不能隨便執行。

如果是小表、測試表，修改欄位通常很快；但如果是正式環境的大表，某些 `ALTER TABLE` 可能會：

- 重建整張表；
- 複製大量資料；
- 產生 metadata lock；
- 阻塞其他 SQL；
- 造成欄位資料被轉換、截斷或遺失；
- 讓應用程式、報表、View、Stored Procedure、批次程式一起壞掉。

這一篇學完後，你應該要能做到：

1. 看懂 `ALTER TABLE` 的常見語法；
2. 正確區分 `ADD COLUMN`、`MODIFY COLUMN`、`CHANGE COLUMN`、`RENAME COLUMN`、`DROP COLUMN`；
3. 知道修改欄位時要重新寫完整欄位定義；
4. 知道新增 `NOT NULL` 欄位、縮短欄位長度、刪除欄位前要檢查什麼；
5. 知道正式環境修改表結構前的基本安全流程。

## 關鍵字

- 主題：修改表、修改欄位、新增欄位、刪除欄位、修改欄位型別、修改預設值、欄位重命名、調整欄位位置、表結構演進
- 英文：alter table, add column, modify column, change column, rename column, drop column, set default, drop default, online DDL, metadata lock
- 常見搜尋：MySQL 修改表、MySQL ALTER TABLE、MySQL 新增欄位、MySQL 修改欄位型別、MySQL 改欄位名稱、MySQL 刪除欄位、MySQL MODIFY CHANGE 差異
- 容易混淆：`MODIFY` vs `CHANGE`、`CHANGE` vs `RENAME COLUMN`、修改預設值 vs 更新既有資料、調整欄位位置 vs 調整查詢結果順序、刪除欄位 vs 刪除表

## 建議回查情境

- 表已經存在，現在要補新欄位時。
- 要修改欄位型別、長度、是否可為 `NULL`、預設值、註解時。
- 想改欄位名稱，但不確定該用 `CHANGE` 還是 `RENAME COLUMN` 時。
- 想刪除欄位，但不確定它有沒有被索引、外鍵、程式碼或報表使用時。
- 想調整欄位順序，但不確定這樣做是否有必要時。
- 正式環境要執行 `ALTER TABLE`，需要先做風險檢查時。

## 30 秒複習入口

- 修改既有表結構，核心命令是 `ALTER TABLE`。
- `ADD COLUMN`：新增欄位。
- `MODIFY COLUMN`：修改欄位定義，但不改欄位名稱。
- `CHANGE COLUMN`：可以同時改欄位名稱和欄位定義。
- `RENAME COLUMN`：只改欄位名稱，不改欄位定義，MySQL 8.0+ 很常用。
- `DROP COLUMN`：刪除欄位，會移除該欄位的資料。
- `ALTER COLUMN ... SET DEFAULT`：只修改欄位預設值。
- `ALTER COLUMN ... DROP DEFAULT`：移除欄位預設值。
- 使用 `MODIFY` 或 `CHANGE` 修改欄位時，要把希望保留的型別屬性完整寫出來，例如 `UNSIGNED`、`NOT NULL`、`DEFAULT`、`COMMENT`。
- 修改欄位預設值只影響之後新增資料時的預設值，不會自動更新既有資料。
- 縮短字串欄位、改數值型別、改 `NULL` 為 `NOT NULL`，都要先檢查既有資料是否符合新規則。
- 刪除欄位前，要先確認索引、外鍵、View、Stored Procedure、排程、報表、應用程式是否還依賴它。
- 正式環境的大表不要直接隨手 `ALTER TABLE`，要先評估資料量、鎖表風險、備份、回滾方案與低峰時段。

## 速查區

### 常見 `ALTER TABLE` 操作總表

| 需求 | 建議語法 | 用途 |
| --- | --- | --- |
| 新增欄位 | `ALTER TABLE t ADD COLUMN c type;` | 在既有表加入新欄位 |
| 一次新增多欄位 | `ALTER TABLE t ADD COLUMN (...);` | 同時新增多個欄位 |
| 修改欄位定義 | `ALTER TABLE t MODIFY COLUMN c new_definition;` | 改型別、長度、`NULL`、預設值、註解、位置 |
| 同時改欄位名與定義 | `ALTER TABLE t CHANGE COLUMN old_c new_c new_definition;` | 舊版常用的欄位改名方式，也可順便改定義 |
| 只改欄位名 | `ALTER TABLE t RENAME COLUMN old_c TO new_c;` | MySQL 8.0+ 推薦用於單純改欄位名 |
| 修改預設值 | `ALTER TABLE t ALTER COLUMN c SET DEFAULT value;` | 只改欄位預設值 |
| 移除預設值 | `ALTER TABLE t ALTER COLUMN c DROP DEFAULT;` | 移除欄位預設值 |
| 刪除欄位 | `ALTER TABLE t DROP COLUMN c;` | 刪除欄位與該欄位資料 |
| 一次刪多欄位 | `ALTER TABLE t DROP COLUMN c1, DROP COLUMN c2;` | 同一條 SQL 刪多個欄位 |
| 調整欄位位置 | `MODIFY ... FIRST / AFTER ...` | 改變欄位在表結構中的顯示順序 |
| 修改表註解 | `ALTER TABLE t COMMENT = '...';` | 修改資料表註解 |
| 修改表預設字元集 | `ALTER TABLE t DEFAULT CHARSET = utf8mb4;` | 影響後續新增欄位的預設字元集 |
| 轉換表字元集 | `ALTER TABLE t CONVERT TO CHARACTER SET utf8mb4;` | 嘗試轉換既有文字欄位內容 |

### `MODIFY`、`CHANGE`、`RENAME COLUMN` 差異

| 語法 | 是否可改欄位名 | 是否可改欄位定義 | 是否需要重寫資料型別 | 適合場景 |
| --- | --- | --- | --- | --- |
| `MODIFY COLUMN c definition` | 否 | 是 | 要 | 只改型別、長度、預設值、是否可空、註解、位置 |
| `CHANGE COLUMN old_c new_c definition` | 是 | 是 | 要 | 同時改欄位名與欄位定義，或相容舊寫法 |
| `RENAME COLUMN old_c TO new_c` | 是 | 否 | 不用 | 只改欄位名，語意最清楚 |

簡單記法：

```text
只改欄位定義：MODIFY
只改欄位名稱：RENAME COLUMN
改欄位名稱 + 改欄位定義：CHANGE
```

### 正式環境修改表前檢查清單

執行 `ALTER TABLE` 前，建議先做這幾件事：

```sql
-- 1. 確認目前資料庫
SELECT DATABASE();

-- 2. 查看完整建表語句
SHOW CREATE TABLE app_user;

-- 3. 查看欄位資訊
SHOW FULL COLUMNS FROM app_user;

-- 4. 查看索引
SHOW INDEX FROM app_user;

-- 5. 查看目標欄位是否存在
SELECT COLUMN_NAME, COLUMN_TYPE, IS_NULLABLE, COLUMN_DEFAULT, COLUMN_COMMENT
FROM INFORMATION_SCHEMA.COLUMNS
WHERE TABLE_SCHEMA = DATABASE()
  AND TABLE_NAME = 'app_user'
  AND COLUMN_NAME = 'phone';
```

正式環境還要額外確認：

- 是否已備份；
- 是否已在測試環境演練；
- 是否有回滾方案；
- 是否會影響線上 API、批次程式、報表、View、Stored Procedure；
- 是否需要低峰時段執行；
- 是否要加上 `ALGORITHM`、`LOCK` 控制執行方式；
- 是否需要 DBA 或資深工程師審查。

## 4.1 `ALTER TABLE` 的基本概念

`ALTER TABLE` 是用來修改既有表結構的語句。

基本骨架如下：

```sql
ALTER TABLE 表名
    修改動作1,
    修改動作2,
    修改動作3;
```

例如：

```sql
ALTER TABLE app_user
    ADD COLUMN phone VARCHAR(20) NULL COMMENT '手機號碼' AFTER email,
    ADD COLUMN last_login_at DATETIME NULL COMMENT '最後登入時間' AFTER updated_at;
```

這代表對 `app_user` 這張表同時做兩件事：

1. 新增 `phone` 欄位；
2. 新增 `last_login_at` 欄位。

MySQL 允許在同一條 `ALTER TABLE` 中放多個修改動作，用逗號分隔。這在需要一次完成多個結構調整時很常見。

### 4.1.1 修改表前先看原始結構

修改表以前，第一步不是直接寫 `ALTER TABLE`，而是先看原表長什麼樣子。

最重要的是：

```sql
SHOW CREATE TABLE app_user;
```

它會顯示完整建表語句，包含：

- 欄位名稱；
- 欄位型別；
- `NULL` / `NOT NULL`；
- `DEFAULT`；
- `COMMENT`；
- 主鍵；
- 索引；
- 唯一約束；
- 外鍵；
- `CHECK` 約束；
- 儲存引擎；
- 字元集；
- 排序規則。

如果只是快速看欄位，可以用：

```sql
DESC app_user;
```

或：

```sql
SHOW FULL COLUMNS FROM app_user;
```

`SHOW FULL COLUMNS` 會比 `DESC` 多看到欄位註解、collation 等資訊。

## 4.2 新增欄位：`ADD COLUMN`

### 4.2.1 基本語法

```sql
ALTER TABLE 表名
ADD [COLUMN] 欄位名 欄位定義 [FIRST | AFTER 某欄位];
```

其中：

| 部分 | 說明 |
| --- | --- |
| `ADD COLUMN` | 新增欄位 |
| `欄位名` | 新欄位名稱 |
| `欄位定義` | 型別、是否可空、預設值、註解等 |
| `FIRST` | 放到第一個欄位 |
| `AFTER 某欄位` | 放在某欄位後面 |

`COLUMN` 通常可以省略，但筆記與實務上建議保留，語意比較清楚。

### 4.2.2 新增普通欄位

假設有一張使用者表：

```sql
CREATE TABLE app_user (
    id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '使用者ID',
    username VARCHAR(50) NOT NULL COMMENT '帳號',
    email VARCHAR(100) NOT NULL COMMENT '電子信箱',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '建立時間',
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新時間',
    PRIMARY KEY (id),
    UNIQUE KEY uk_app_user_username (username),
    UNIQUE KEY uk_app_user_email (email)
) ENGINE = InnoDB
  DEFAULT CHARSET = utf8mb4
  COLLATE = utf8mb4_0900_ai_ci
  COMMENT = '使用者表';
```

現在想新增手機欄位：

```sql
ALTER TABLE app_user
ADD COLUMN phone VARCHAR(20) NULL COMMENT '手機號碼' AFTER email;
```

說明：

| 寫法 | 意義 |
| --- | --- |
| `phone` | 新欄位名稱 |
| `VARCHAR(20)` | 字串型別，最多 20 個字元 |
| `NULL` | 允許沒有手機號碼 |
| `COMMENT '手機號碼'` | 欄位註解 |
| `AFTER email` | 放在 `email` 欄位後面 |

### 4.2.3 新增帶預設值的欄位

例如新增會員狀態欄位：

```sql
ALTER TABLE app_user
ADD COLUMN status TINYINT NOT NULL DEFAULT 1 COMMENT '狀態：1啟用，0停用' AFTER phone;
```

這樣之後新增資料時，如果沒有指定 `status`，MySQL 會使用預設值 `1`。

注意：

> 預設值主要影響「之後新增資料」時的欄位值；對於既有資料，實際結果會受到 MySQL 版本、欄位定義、執行方式與資料表狀態影響。正式環境中，不要只靠猜測，應先在測試環境驗證。

比較安全、可控的做法是分三步：

```sql
-- 1. 先新增可為 NULL 的欄位，降低既有資料不符合規則的風險
ALTER TABLE app_user
ADD COLUMN status TINYINT NULL COMMENT '狀態：1啟用，0停用' AFTER phone;

-- 2. 回填既有資料
UPDATE app_user
SET status = 1
WHERE status IS NULL;

-- 3. 確認沒有 NULL 後，再改成 NOT NULL + DEFAULT
ALTER TABLE app_user
MODIFY COLUMN status TINYINT NOT NULL DEFAULT 1 COMMENT '狀態：1啟用，0停用' AFTER phone;
```

這種流程比一次新增 `NOT NULL` 欄位更適合正式環境，因為每一步都可以檢查。

### 4.2.4 新增欄位到第一個位置

```sql
ALTER TABLE app_user
ADD COLUMN tenant_id BIGINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '租戶ID' FIRST;
```

這會把 `tenant_id` 放在表結構的第一個欄位。

不過實務上要注意：

> 欄位順序通常不應該影響程式邏輯。查詢時應該明確寫欄位名稱，不要依賴 `SELECT *` 的欄位順序。

例如不要這樣依賴順序：

```sql
SELECT * FROM app_user;
```

正式程式建議明確寫：

```sql
SELECT id, username, email, phone, status
FROM app_user;
```

### 4.2.5 一次新增多個欄位

MySQL 支援一條 `ALTER TABLE` 新增多個欄位。

寫法一：重複多個 `ADD COLUMN`：

```sql
ALTER TABLE app_user
ADD COLUMN nickname VARCHAR(50) NULL COMMENT '暱稱' AFTER username,
ADD COLUMN last_login_at DATETIME NULL COMMENT '最後登入時間' AFTER updated_at;
```

寫法二：使用括號新增多個欄位：

```sql
ALTER TABLE app_user
ADD COLUMN (
    avatar_url VARCHAR(500) NULL COMMENT '頭像URL',
    bio VARCHAR(500) NULL COMMENT '個人簡介'
);
```

實務上我比較建議第一種，因為每個欄位可以清楚控制 `FIRST` / `AFTER`。

## 4.3 修改欄位定義：`MODIFY COLUMN`

### 4.3.1 基本語法

```sql
ALTER TABLE 表名
MODIFY [COLUMN] 欄位名 新欄位定義 [FIRST | AFTER 某欄位];
```

`MODIFY COLUMN` 用於修改欄位定義，但不修改欄位名稱。

可以修改的內容包括：

- 資料型別；
- 長度；
- `NULL` / `NOT NULL`；
- `DEFAULT`；
- `COMMENT`；
- `VISIBLE` / `INVISIBLE`；
- 欄位位置。

### 4.3.2 修改欄位長度

例如把 `username` 從 `VARCHAR(50)` 改成 `VARCHAR(80)`：

```sql
ALTER TABLE app_user
MODIFY COLUMN username VARCHAR(80) NOT NULL COMMENT '帳號';
```

注意，這裡不是只寫：

```sql
ALTER TABLE app_user
MODIFY COLUMN username VARCHAR(80);
```

因為這樣可能會讓原本的 `NOT NULL`、`DEFAULT`、`COMMENT` 等屬性沒有被保留下來。

`MODIFY` / `CHANGE` 的重要原則是：

> 你希望修改後欄位擁有哪些屬性，就要在新的欄位定義中完整寫出來。

### 4.3.3 錯誤示範：少寫屬性造成欄位規則被改掉

假設原欄位是：

```sql
balance DECIMAL(12, 2) UNSIGNED NOT NULL DEFAULT 0.00 COMMENT '帳戶餘額'
```

你只是想把精度改成 `DECIMAL(14,2)`，但寫成：

```sql
ALTER TABLE app_user
MODIFY COLUMN balance DECIMAL(14, 2);
```

這樣很危險，因為你沒有重新寫出：

- `UNSIGNED`；
- `NOT NULL`；
- `DEFAULT 0.00`；
- `COMMENT '帳戶餘額'`。

比較正確的寫法是：

```sql
ALTER TABLE app_user
MODIFY COLUMN balance DECIMAL(14, 2) UNSIGNED NOT NULL DEFAULT 0.00 COMMENT '帳戶餘額';
```

這是 `ALTER TABLE` 很重要的細節，不能只記「`MODIFY` 可以改型別」。

### 4.3.4 修改欄位為 `NOT NULL`

假設 `phone` 原本允許 `NULL`，現在想改成不可為空：

```sql
ALTER TABLE app_user
MODIFY COLUMN phone VARCHAR(20) NOT NULL COMMENT '手機號碼';
```

但在執行之前，應該先檢查是否有既有資料是 `NULL`：

```sql
SELECT COUNT(*) AS null_phone_count
FROM app_user
WHERE phone IS NULL;
```

如果有資料是 `NULL`，應先補值：

```sql
UPDATE app_user
SET phone = ''
WHERE phone IS NULL;
```

然後再改欄位：

```sql
ALTER TABLE app_user
MODIFY COLUMN phone VARCHAR(20) NOT NULL COMMENT '手機號碼';
```

不過，如果手機號碼真的可能沒有資料，硬改成 `NOT NULL` 不一定合理。應該回到業務規則判斷：

> 這個欄位到底是不是業務上必填？

### 4.3.5 縮短欄位長度前先檢查資料

假設 `email` 原本是 `VARCHAR(100)`，你想縮短成 `VARCHAR(60)`。

不要直接做：

```sql
ALTER TABLE app_user
MODIFY COLUMN email VARCHAR(60) NOT NULL COMMENT '電子信箱';
```

應先檢查是否有超過 60 字元的資料：

```sql
SELECT id, email, CHAR_LENGTH(email) AS email_length
FROM app_user
WHERE CHAR_LENGTH(email) > 60;
```

如果查得出資料，代表直接縮短可能造成資料截斷或失敗。應先處理資料，再修改欄位。

### 4.3.6 修改欄位註解

如果只是修改欄位註解，也要重新寫完整欄位定義：

```sql
ALTER TABLE app_user
MODIFY COLUMN email VARCHAR(100) NOT NULL COMMENT '使用者電子信箱';
```

注意：

> `COMMENT` 不是附加在原欄位上的獨立操作；你通常需要在欄位定義中重新寫出型別與其他屬性。

### 4.3.7 調整欄位位置

例如把 `phone` 移到 `email` 後面：

```sql
ALTER TABLE app_user
MODIFY COLUMN phone VARCHAR(20) NULL COMMENT '手機號碼' AFTER email;
```

或者移到第一個欄位：

```sql
ALTER TABLE app_user
MODIFY COLUMN phone VARCHAR(20) NULL COMMENT '手機號碼' FIRST;
```

實務提醒：

- 調整欄位位置通常只是讓 `DESC` 或 `SELECT *` 看起來比較順；
- 正式程式不應該依賴欄位順序；
- 對大表來說，調整欄位位置可能是昂貴操作；
- 如果只是查詢結果想改順序，應該改 `SELECT` 欄位順序，不一定要改表結構。

例如：

```sql
SELECT id, username, email, phone, created_at
FROM app_user;
```

## 4.4 修改欄位預設值：`ALTER COLUMN SET DEFAULT / DROP DEFAULT`

如果只是修改欄位預設值，不一定要用 `MODIFY COLUMN`。

### 4.4.1 設定預設值

```sql
ALTER TABLE app_user
ALTER COLUMN status SET DEFAULT 1;
```

這代表之後新增資料時，如果沒有指定 `status`，預設使用 `1`。

### 4.4.2 移除預設值

```sql
ALTER TABLE app_user
ALTER COLUMN status DROP DEFAULT;
```

### 4.4.3 預設值不會自動更新既有資料

假設原本資料裡有：

```text
id | username | status
---+----------+-------
1  | tom      | NULL
2  | mary     | NULL
```

你執行：

```sql
ALTER TABLE app_user
ALTER COLUMN status SET DEFAULT 1;
```

這不代表既有資料中的 `NULL` 會自動變成 `1`。

若要更新既有資料，要另外執行 `UPDATE`：

```sql
UPDATE app_user
SET status = 1
WHERE status IS NULL;
```

所以要清楚區分：

| 操作 | 影響對象 |
| --- | --- |
| `ALTER COLUMN ... SET DEFAULT` | 之後新增資料時的預設值 |
| `UPDATE ... SET ...` | 既有資料內容 |

## 4.5 重命名欄位：`RENAME COLUMN` 與 `CHANGE COLUMN`

### 4.5.1 MySQL 8.0+：只改名建議用 `RENAME COLUMN`

如果只是把 `username` 改成 `login_name`，且不修改欄位型別與其他屬性，建議用：

```sql
ALTER TABLE app_user
RENAME COLUMN username TO login_name;
```

優點是語意非常清楚：

```text
rename column：只改欄位名稱
```

不需要重新寫資料型別，因此比較不容易漏掉 `NOT NULL`、`DEFAULT`、`COMMENT` 等欄位屬性。

### 4.5.2 同時改名與改定義：用 `CHANGE COLUMN`

基本語法：

```sql
ALTER TABLE 表名
CHANGE [COLUMN] 舊欄位名 新欄位名 新欄位定義 [FIRST | AFTER 某欄位];
```

例如把 `login_name` 改成 `account_name`，同時把長度改成 `VARCHAR(80)`：

```sql
ALTER TABLE app_user
CHANGE COLUMN login_name account_name VARCHAR(80) NOT NULL COMMENT '登入帳號';
```

`CHANGE COLUMN` 有一個很重要的特性：

> 它必須寫「舊欄位名、新欄位名、新欄位定義」。

即使不改欄位名，也要寫兩次欄位名。

例如你想用 `CHANGE` 修改 `account_name` 的型別但不改名：

```sql
ALTER TABLE app_user
CHANGE COLUMN account_name account_name VARCHAR(100) NOT NULL COMMENT '登入帳號';
```

但這種情況其實用 `MODIFY` 更清楚：

```sql
ALTER TABLE app_user
MODIFY COLUMN account_name VARCHAR(100) NOT NULL COMMENT '登入帳號';
```

### 4.5.3 改名後仍要檢查依賴關係

欄位改名不只是資料庫內部的事情，還可能影響：

- Java Entity；
- MyBatis XML；
- JPA / Hibernate mapping；
- SQL 查詢；
- View；
- Stored Procedure；
- Trigger；
- 報表；
- 批次程式；
- 前端欄位名稱；
- API JSON 欄位；
- Excel 匯出欄位。

資料庫可能可以幫你更新部分索引或外鍵引用，但不代表會自動修正應用程式、View、Stored Procedure 或報表中的 SQL。

所以欄位改名前要先搜尋專案：

```text
username
login_name
account_name
```

如果是 MyBatis 專案，至少要找：

```text
resultMap
column="username"
username
#{username}
${username}
```

## 4.6 刪除欄位：`DROP COLUMN`

### 4.6.1 基本語法

```sql
ALTER TABLE 表名
DROP [COLUMN] 欄位名;
```

例如刪除 `bio` 欄位：

```sql
ALTER TABLE app_user
DROP COLUMN bio;
```

這會從表中移除 `bio` 欄位，該欄位保存的資料也會一起消失。

### 4.6.2 一次刪除多個欄位

```sql
ALTER TABLE app_user
DROP COLUMN avatar_url,
DROP COLUMN bio;
```

注意：

- 每個欄位都要寫一次 `DROP COLUMN`；
- 不要寫成 `DROP COLUMN avatar_url, bio`；
- 刪除欄位前最好先確認備份與依賴關係。

### 4.6.3 MySQL 不支援 `DROP COLUMN IF EXISTS`

在 MySQL 的 `ALTER TABLE` 語法中，刪欄位通常不能直接寫：

```sql
ALTER TABLE app_user
DROP COLUMN IF EXISTS bio;
```

比較穩妥的做法是先查欄位是否存在：

```sql
SELECT COLUMN_NAME
FROM INFORMATION_SCHEMA.COLUMNS
WHERE TABLE_SCHEMA = DATABASE()
  AND TABLE_NAME = 'app_user'
  AND COLUMN_NAME = 'bio';
```

確認存在後再執行：

```sql
ALTER TABLE app_user
DROP COLUMN bio;
```

### 4.6.4 刪除被索引使用的欄位

刪欄位前先看索引：

```sql
SHOW INDEX FROM app_user;
```

如果欄位在索引裡，刪除時可能需要先調整或刪除相關索引。

例如：

```sql
ALTER TABLE app_user
DROP INDEX idx_app_user_phone;

ALTER TABLE app_user
DROP COLUMN phone;
```

如果欄位是唯一索引的一部分，刪除前更要小心，因為那可能代表一條重要業務規則。

### 4.6.5 刪除被外鍵使用的欄位

假設有一張訂單表：

```sql
CREATE TABLE user_order (
    id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '訂單ID',
    user_id BIGINT UNSIGNED NOT NULL COMMENT '使用者ID',
    order_no VARCHAR(50) NOT NULL COMMENT '訂單編號',
    PRIMARY KEY (id),
    CONSTRAINT fk_user_order_user
        FOREIGN KEY (user_id) REFERENCES app_user(id)
) ENGINE = InnoDB
  DEFAULT CHARSET = utf8mb4
  COLLATE = utf8mb4_0900_ai_ci
  COMMENT = '訂單表';
```

如果你想刪除 `user_order.user_id`，需要先刪除外鍵：

```sql
ALTER TABLE user_order
DROP FOREIGN KEY fk_user_order_user;

ALTER TABLE user_order
DROP COLUMN user_id;
```

外鍵名稱可以用：

```sql
SHOW CREATE TABLE user_order;
```

或查詢：

```sql
SELECT CONSTRAINT_NAME, TABLE_NAME, COLUMN_NAME, REFERENCED_TABLE_NAME, REFERENCED_COLUMN_NAME
FROM INFORMATION_SCHEMA.KEY_COLUMN_USAGE
WHERE TABLE_SCHEMA = DATABASE()
  AND TABLE_NAME = 'user_order'
  AND COLUMN_NAME = 'user_id';
```

### 4.6.6 正式環境刪欄位的建議流程

刪欄位是高風險操作，因為它會移除資料，且通常不容易回復。

比較安全的流程是：

```text
1. 確認欄位真的不再使用
2. 搜尋程式碼、SQL、報表、View、Stored Procedure
3. 先停止寫入該欄位，或讓程式不再依賴該欄位
4. 觀察一段時間
5. 備份資料
6. 在測試環境演練 DROP COLUMN
7. 低峰時段正式刪除
8. 刪除後檢查應用程式與錯誤日誌
```

如果你不確定欄位是否還有用，可以先不要刪，而是採用「停用欄位」策略：

```text
先不再寫入 → 不再讀取 → 觀察 → 備份 → 最後刪除
```

## 4.7 修改表註解、表選項與字元集

`ALTER TABLE` 不只可以修改欄位，也可以修改表本身的選項。

### 4.7.1 修改表註解

```sql
ALTER TABLE app_user
COMMENT = '系統使用者資料表';
```

### 4.7.2 修改表的預設字元集

```sql
ALTER TABLE app_user
DEFAULT CHARACTER SET = utf8mb4
COLLATE = utf8mb4_0900_ai_ci;
```

這代表修改表層級的預設字元集與排序規則。

注意：

> 這主要影響之後新增的文字欄位。如果要轉換既有文字欄位內容，不能只靠 `DEFAULT CHARACTER SET`。

### 4.7.3 轉換既有文字欄位的字元集

如果要嘗試轉換既有文字欄位，可以使用：

```sql
ALTER TABLE app_user
CONVERT TO CHARACTER SET utf8mb4
COLLATE utf8mb4_0900_ai_ci;
```

但這種操作正式環境要非常小心，尤其是：

- 表很大；
- 欄位有索引；
- 欄位參與外鍵；
- 原本資料可能有亂碼；
- 應用程式連線字元集設定不一致。

如果只是讓未來新增欄位使用 `utf8mb4`，通常只要改表預設字元集即可；如果要處理既有資料，必須先確認資料實際編碼狀態。

## 4.8 控制執行方式：`ALGORITHM` 與 `LOCK`

在 InnoDB 中，部分 `ALTER TABLE` 可以使用 online DDL，以降低對線上讀寫的影響。

常見語法：

```sql
ALTER TABLE app_user
ADD COLUMN last_login_ip VARCHAR(45) NULL COMMENT '最後登入IP',
ALGORITHM = INSTANT;
```

或：

```sql
ALTER TABLE app_user
MODIFY COLUMN phone VARCHAR(30) NULL COMMENT '手機號碼',
ALGORITHM = INPLACE,
LOCK = NONE;
```

這裡先不需要把 online DDL 的所有細節背完，但要知道幾個方向：

| 選項 | 大意 |
| --- | --- |
| `ALGORITHM=INSTANT` | 只改 metadata 或可以瞬間完成的操作，限制較多 |
| `ALGORITHM=INPLACE` | 盡量原地處理，可能仍會重建資料或花時間 |
| `ALGORITHM=COPY` | 建立新表、複製資料，再替換，通常最重 |
| `LOCK=NONE` | 希望允許併發讀寫 |
| `LOCK=SHARED` | 允許讀，限制寫 |
| `LOCK=EXCLUSIVE` | 排他鎖，讀寫都可能受阻 |

重要觀念：

> 不是每種修改都支援 `INSTANT` 或 `LOCK=NONE`。如果你指定了不支援的組合，MySQL 可能直接報錯。

正式環境中，`ALTER TABLE` 的成本不只看語法，也要看：

- MySQL 版本；
- 儲存引擎；
- 表大小；
- 是否有索引；
- 是否有外鍵；
- 欄位型別；
- 是否改變資料實際儲存格式；
- 是否需要重建表。

## 4.9 綜合範例：使用者表演進

假設一開始有這張表：

```sql
CREATE TABLE app_user (
    id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '使用者ID',
    username VARCHAR(50) NOT NULL COMMENT '帳號',
    email VARCHAR(100) NOT NULL COMMENT '電子信箱',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '建立時間',
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新時間',
    PRIMARY KEY (id),
    UNIQUE KEY uk_app_user_username (username),
    UNIQUE KEY uk_app_user_email (email)
) ENGINE = InnoDB
  DEFAULT CHARSET = utf8mb4
  COLLATE = utf8mb4_0900_ai_ci
  COMMENT = '使用者表';
```

現在需求變更：

1. 新增手機欄位 `phone`；
2. 新增狀態欄位 `status`，預設啟用；
3. 把 `username` 改名為 `login_name`；
4. 把 `email` 註解改得更清楚；
5. 新增最後登入時間 `last_login_at`；
6. 刪除不再使用的 `nickname` 欄位。

### 4.9.1 先檢查原表

```sql
SHOW CREATE TABLE app_user;
SHOW FULL COLUMNS FROM app_user;
SHOW INDEX FROM app_user;
```

### 4.9.2 新增欄位

```sql
ALTER TABLE app_user
ADD COLUMN phone VARCHAR(20) NULL COMMENT '手機號碼' AFTER email,
ADD COLUMN status TINYINT NOT NULL DEFAULT 1 COMMENT '狀態：1啟用，0停用' AFTER phone,
ADD COLUMN last_login_at DATETIME NULL COMMENT '最後登入時間' AFTER updated_at;
```

### 4.9.3 改欄位名

```sql
ALTER TABLE app_user
RENAME COLUMN username TO login_name;
```

如果你的 MySQL 版本較舊，不支援 `RENAME COLUMN`，可以使用 `CHANGE COLUMN`：

```sql
ALTER TABLE app_user
CHANGE COLUMN username login_name VARCHAR(50) NOT NULL COMMENT '登入帳號';
```

### 4.9.4 修改欄位註解

```sql
ALTER TABLE app_user
MODIFY COLUMN email VARCHAR(100) NOT NULL COMMENT '使用者電子信箱';
```

### 4.9.5 刪除欄位前先確認

```sql
SELECT COLUMN_NAME
FROM INFORMATION_SCHEMA.COLUMNS
WHERE TABLE_SCHEMA = DATABASE()
  AND TABLE_NAME = 'app_user'
  AND COLUMN_NAME = 'nickname';
```

確認存在且不再使用後：

```sql
ALTER TABLE app_user
DROP COLUMN nickname;
```

### 4.9.6 修改後再檢查

```sql
SHOW CREATE TABLE app_user;
SHOW FULL COLUMNS FROM app_user;
```

## 4.10 常見錯誤整理

### 錯誤 1：`MODIFY` 時忘記保留原本屬性

錯誤寫法：

```sql
ALTER TABLE app_user
MODIFY COLUMN email VARCHAR(150);
```

可能問題：

- 原本 `NOT NULL` 消失；
- 原本 `COMMENT` 消失；
- 原本 `DEFAULT` 消失；
- 原本字元集或其他屬性可能被改變。

較好寫法：

```sql
ALTER TABLE app_user
MODIFY COLUMN email VARCHAR(150) NOT NULL COMMENT '使用者電子信箱';
```

### 錯誤 2：改欄位名後只改資料庫，忘記改程式

```sql
ALTER TABLE app_user
RENAME COLUMN username TO login_name;
```

如果 Java Entity、MyBatis XML、SQL、前端欄位仍然使用 `username`，程式就可能報錯。

改欄位名通常要搭配程式碼一起改。

### 錯誤 3：直接刪除欄位，沒有確認依賴

```sql
ALTER TABLE app_user
DROP COLUMN phone;
```

刪除前應至少確認：

```sql
SHOW INDEX FROM app_user;
SHOW CREATE TABLE app_user;
```

並搜尋專案中是否還使用：

```text
phone
getPhone
setPhone
phone)
phone,
column="phone"
#{phone}
```

### 錯誤 4：以為修改預設值會更新既有資料

```sql
ALTER TABLE app_user
ALTER COLUMN status SET DEFAULT 1;
```

這不會自動把既有的 `NULL` 改成 `1`。

要更新既有資料，需要：

```sql
UPDATE app_user
SET status = 1
WHERE status IS NULL;
```

### 錯誤 5：為了欄位順序頻繁改表

```sql
ALTER TABLE app_user
MODIFY COLUMN phone VARCHAR(20) NULL COMMENT '手機號碼' AFTER email;
```

如果只是查詢時想讓欄位順序更好看，不一定要改表。

可以改查詢：

```sql
SELECT id, login_name, email, phone, status, created_at
FROM app_user;
```

## 一句話對比

- `ADD COLUMN`：新增欄位。
- `MODIFY COLUMN`：修改欄位定義，不改欄位名。
- `CHANGE COLUMN`：可以同時改欄位名與欄位定義。
- `RENAME COLUMN`：只改欄位名。
- `ALTER COLUMN ... SET DEFAULT`：修改預設值。
- `ALTER COLUMN ... DROP DEFAULT`：移除預設值。
- `DROP COLUMN`：刪除欄位與欄位資料。
- `FIRST` / `AFTER`：調整欄位在表結構中的位置。
- `ALGORITHM` / `LOCK`：控制部分 DDL 的執行方式與併發影響。
