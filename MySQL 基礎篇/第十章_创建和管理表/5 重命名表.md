# 5 重命名表

返回章節：[第十章_创建和管理表](./README.md)

## 本節導讀

這一節處理的是：**資料表已經存在，現在想把表名改掉時，應該怎麼做。**

表重命名看起來只是「改一個名字」，但在真實專案中，它通常不是單純的語法問題，而是**依賴關係問題**。

因為一張表名可能被很多地方使用，例如：

- 後端程式中的 SQL；
- Mapper XML、Repository、DAO；
- View；
- Stored Procedure / Function；
- Trigger；
- Event Scheduler；
- 批次程式；
- 報表 SQL；
- ETL 腳本；
- 權限設定；
- 監控、備份、資料同步或資料比對腳本。

所以「重命名表」真正要學的不是只有：

```sql
RENAME TABLE old_table TO new_table;
```

而是要知道：

1. 單表改名怎麼寫；
2. 多表一次改名怎麼寫；
3. 如何交換兩張表的名稱；
4. `RENAME TABLE` 和 `ALTER TABLE ... RENAME` 差在哪裡；
5. 改名後哪些東西不會自動幫你改；
6. 正式環境改名前要檢查什麼。

這一篇學完後，你應該要能做到：

- 正確使用 `RENAME TABLE` 修改表名；
- 正確使用 `ALTER TABLE ... RENAME` 修改單一表名；
- 知道多表重命名會按照從左到右的順序執行；
- 知道同一條 `RENAME TABLE` 發生錯誤時，整句會失敗，不會留下部分改名結果；
- 知道 `RENAME TABLE` 是 DDL，會造成 implicit commit，不能當成一般 DML 用 `ROLLBACK` 復原；
- 知道改名後要檢查程式、View、Stored Procedure、Trigger、Event、權限與外鍵 / 檢查約束名稱。

## 關鍵字

- 主題：重命名表、修改表名、表改名、多表改名、跨資料庫移動表、交換表名
- 英文：rename table, alter table rename, table rename, metadata lock, implicit commit
- 常見搜尋：MySQL 重命名表、MySQL 改表名、MySQL rename table、MySQL alter table rename、MySQL 一次改多個表名、MySQL 交換兩張表名
- 容易混淆：重命名表 vs 重命名欄位、`RENAME TABLE` vs `ALTER TABLE ... RENAME`、表改名 vs 資料庫改名、改表名 vs 複製表、DDL atomic vs transaction rollback

## 建議回查情境

- 表名一開始命名不好，後來想改成更符合業務語意的名稱時。
- 想把臨時表、舊表、正式表的名稱交換時。
- 想一次修改多張表的名稱時。
- 想把表從一個 database 移到另一個 database 時。
- 想知道 `RENAME TABLE` 和 `ALTER TABLE ... RENAME` 該選哪一個時。
- 正式環境要改表名，需要先做影響範圍檢查時。

## 30 秒複習入口

- 單純改表名，可以用 `RENAME TABLE old_table TO new_table;`。
- 單表改名，也可以用 `ALTER TABLE old_table RENAME TO new_table;`。
- 一次改多張表名，要用 `RENAME TABLE`。
- `RENAME TABLE` 多組改名會按照**從左到右**執行。
- 要交換兩張表名，通常需要一個中間表名，例如 `tmp_table`。
- `RENAME TABLE` 如果其中一個改名出錯，整句會失敗，不會保留部分成功結果。
- `RENAME TABLE` 是 DDL，會造成 implicit commit，不能依賴 `ROLLBACK` 復原。
- 改表名不會改動表內資料本身，但會影響所有引用舊表名的 SQL、程式、View、Procedure、Trigger、Event、報表與腳本。
- 表名專屬權限不會自動搬到新表名，需要手動調整授權。
- `RENAME TABLE` 不能用來改 `TEMPORARY` table；臨時表要用 `ALTER TABLE`。
- 如果表有 Trigger，不能直接用重命名方式把表移到不同 database，否則會遇到 trigger schema 不一致的問題。

## 速查區

### 表重命名常用語法

| 需求 | 語法 | 說明 |
| --- | --- | --- |
| 單表改名 | `RENAME TABLE old_table TO new_table;` | 最直覺的表改名語法 |
| 多表改名 | `RENAME TABLE old1 TO new1, old2 TO new2;` | 一次改多張表名 |
| 交換表名 | `RENAME TABLE a TO tmp, b TO a, tmp TO b;` | 需要中間名稱 |
| 單表改名 | `ALTER TABLE old_table RENAME TO new_table;` | `ALTER TABLE` 寫法 |
| 移到其他 database | `RENAME TABLE db1.t TO db2.t;` | 本質上是把表移到另一個 schema |
| 臨時表改名 | `ALTER TABLE temp_old RENAME TO temp_new;` | `RENAME TABLE` 不適用於 `TEMPORARY` table |

### `RENAME TABLE` vs `ALTER TABLE ... RENAME`

| 比較項目 | `RENAME TABLE` | `ALTER TABLE ... RENAME` |
| --- | --- | --- |
| 是否可改表名 | 可以 | 可以 |
| 是否可一次改多張表 | 可以 | 不適合，一次主要處理一張表 |
| 是否可交換表名 | 可以 | 不適合 |
| 是否可與其他 `ALTER TABLE` 操作放在同一句 | 不可以 | 可以，但正式環境不建議隨便混在一起 |
| 是否可改 `TEMPORARY` table | 不可以 | 可以 |
| 適合場景 | 單純改名、批量改名、交換表名 | 單表改名，或已經在做表結構調整時順便改名 |

簡單記法：

```text
純改名、多表改名、交換表名：RENAME TABLE
單表改名、想和 ALTER TABLE 操作放一起：ALTER TABLE ... RENAME
```

### 正式環境改表名前檢查清單

改表名前，建議至少做這些檢查：

```sql
-- 1. 確認目前所在 database
SELECT DATABASE();

-- 2. 確認舊表存在
SHOW TABLES LIKE 'old_table';

-- 3. 確認新表名還沒有被使用
SHOW TABLES LIKE 'new_table';

-- 4. 看完整建表語句
SHOW CREATE TABLE old_table;

-- 5. 檢查這張表是否有 Trigger
SELECT TRIGGER_NAME, EVENT_MANIPULATION, ACTION_TIMING
FROM INFORMATION_SCHEMA.TRIGGERS
WHERE TRIGGER_SCHEMA = DATABASE()
  AND EVENT_OBJECT_TABLE = 'old_table';

-- 6. 檢查有哪些外鍵關係指向它，或它指向別人
SELECT TABLE_NAME, COLUMN_NAME, CONSTRAINT_NAME,
       REFERENCED_TABLE_NAME, REFERENCED_COLUMN_NAME
FROM INFORMATION_SCHEMA.KEY_COLUMN_USAGE
WHERE TABLE_SCHEMA = DATABASE()
  AND (
        TABLE_NAME = 'old_table'
        OR REFERENCED_TABLE_NAME = 'old_table'
      );

-- 7. 粗略搜尋 View 是否引用舊表名
SELECT TABLE_NAME
FROM INFORMATION_SCHEMA.VIEWS
WHERE TABLE_SCHEMA = DATABASE()
  AND VIEW_DEFINITION LIKE '%old_table%';

-- 8. 粗略搜尋 Stored Procedure / Function 是否引用舊表名
SELECT ROUTINE_NAME, ROUTINE_TYPE
FROM INFORMATION_SCHEMA.ROUTINES
WHERE ROUTINE_SCHEMA = DATABASE()
  AND ROUTINE_DEFINITION LIKE '%old_table%';

-- 9. 粗略搜尋 Event 是否引用舊表名
SELECT EVENT_NAME
FROM INFORMATION_SCHEMA.EVENTS
WHERE EVENT_SCHEMA = DATABASE()
  AND EVENT_DEFINITION LIKE '%old_table%';
```

注意：

- 上面這些 `LIKE '%old_table%'` 只能當作輔助檢查，不能保證 100% 找出所有引用。
- 真正正式環境還要搭配：程式碼全域搜尋、Mapper XML 搜尋、報表 SQL 搜尋、批次程式搜尋、排程搜尋、部署文件搜尋。
- 如果舊表名很短，例如 `user`、`log`，搜尋結果可能很多誤判；建議搭配資料庫名稱、反引號或上下文一起找。

## 5.1 表重命名的核心觀念

重命名表的本質是：**修改資料表的名稱與資料字典中的 metadata。**

它通常不會改變：

- 表內資料；
- 欄位定義；
- 主鍵；
- 索引；
- 大多數表結構本身。

但是它會改變：

- 表在 SQL 中被引用時的名稱；
- 部分內部產生的約束名稱；
- 資料庫 metadata 中記錄的表名；
- 程式、報表、腳本要使用的表名。

所以你要把「重命名表」理解成：

```text
資料還在，但是入口名稱換了。
```

如果程式還在查舊表名：

```sql
SELECT * FROM old_table;
```

改名後它就會找不到表。

必須改成：

```sql
SELECT * FROM new_table;
```

### 5.1.1 表重命名是 DDL，不是普通更新

`RENAME TABLE` 和 `ALTER TABLE ... RENAME` 都屬於 DDL 操作。

這代表它們和下面這種 DML 不一樣：

```sql
UPDATE employee
SET salary = salary + 1000
WHERE id = 1;
```

DML 修改的是資料內容；DDL 修改的是資料庫物件定義。

因此在交易觀念上要特別小心：

```sql
START TRANSACTION;

RENAME TABLE old_table TO new_table;

ROLLBACK;
```

不要以為最後的 `ROLLBACK` 一定可以把表名改回來。

`RENAME TABLE` 屬於會造成 implicit commit 的 DDL。也就是說，它會隱式結束目前交易，不能當成普通 DML 一樣依靠交易回滾。

### 5.1.2 DDL atomic 不等於可以 ROLLBACK

這裡有一個很容易混淆的觀念：

```text
RENAME TABLE 是 atomic。
但 atomic 不等於你可以用 ROLLBACK 復原。
```

對 `RENAME TABLE` 而言，atomic 比較接近：

> 同一條 `RENAME TABLE` 中，如果其中一個改名失敗，整條語句會失敗，不會留下部分表已改名、部分表沒改名的狀態。

例如：

```sql
RENAME TABLE
    old_table1 TO new_table1,
    old_table2 TO new_table2;
```

如果 `new_table2` 已經存在而導致錯誤，整句會失敗，不應該留下只有 `old_table1` 改成功的中間結果。

但這不代表你可以這樣使用：

```sql
START TRANSACTION;
RENAME TABLE old_table TO new_table;
ROLLBACK;
```

然後期待 `new_table` 自動變回 `old_table`。

正確理解：

```text
atomic：這條 DDL 本身成功就全部成功，失敗就全部失敗。
rollback：使用者交易可以撤銷前面操作。
```

`RENAME TABLE` 要靠事前備份、明確的反向 SQL、部署流程與低峰時段控制風險，而不是靠 `ROLLBACK`。

## 5.2 使用 `RENAME TABLE` 重命名表

`RENAME TABLE` 是最常見、最直接的表改名方式。

基本語法：

```sql
RENAME TABLE old_table_name TO new_table_name;
```

例如：

```sql
RENAME TABLE emp TO employee;
```

執行後：

```sql
SHOW TABLES LIKE 'emp';
SHOW TABLES LIKE 'employee';
```

結果應該是：

- `emp` 不存在；
- `employee` 存在。

### 5.2.1 單表改名範例

先建立一張示範表：

```sql
CREATE TABLE emp (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(50) NOT NULL,
    hired_at DATE NULL
) ENGINE = InnoDB
  DEFAULT CHARSET = utf8mb4
  COMMENT = '員工表';
```

確認表存在：

```sql
SHOW TABLES LIKE 'emp';
```

重命名：

```sql
RENAME TABLE emp TO employee;
```

確認結果：

```sql
SHOW TABLES LIKE 'emp';
SHOW TABLES LIKE 'employee';
SHOW CREATE TABLE employee;
```

重命名後，原本的資料仍然在：

```sql
SELECT * FROM employee;
```

但是這句會失敗：

```sql
SELECT * FROM emp;
```

因為舊表名已不存在。

### 5.2.2 一次重命名多張表

`RENAME TABLE` 可以一次改多張表名：

```sql
RENAME TABLE
    emp TO employee,
    dept TO department;
```

這種寫法常見於：

- 統一表名規範；
- 表名前綴調整；
- 臨時表切換；
- 版本升級時多張表一起改名。

範例：

```sql
RENAME TABLE
    old_user TO app_user,
    old_order TO app_order,
    old_order_item TO app_order_item;
```

這樣比寫三條 SQL 更容易保持一致性。

### 5.2.3 多表改名的執行順序：從左到右

`RENAME TABLE` 中有多組改名時，MySQL 會依照語句中列出的順序，**從左到右**處理。

這一點在交換表名時很重要。

錯誤示範：

```sql
RENAME TABLE old_table TO new_table,
             new_table TO old_table;
```

如果 `new_table` 本來就存在，第一步 `old_table TO new_table` 就會撞名。

正確做法是使用中間名稱：

```sql
RENAME TABLE
    old_table TO tmp_table,
    new_table TO old_table,
    tmp_table TO new_table;
```

這常用於「正式表」與「新版本表」切換：

```sql
RENAME TABLE
    product TO product_old,
    product_new TO product;
```

如果只是兩張表交換名稱，建議使用三段式：

```sql
RENAME TABLE
    product TO product_tmp,
    product_new TO product,
    product_tmp TO product_new;
```

這樣比較不容易撞名，也比較容易理解。

### 5.2.4 使用 `RENAME TABLE` 將表移到另一個 database

`RENAME TABLE` 也可以把表從一個 database 移到另一個 database：

```sql
RENAME TABLE current_db.employee TO archive_db.employee;
```

這代表：

- 原本在 `current_db` 的 `employee` 被移走；
- 新表位置變成 `archive_db.employee`。

操作前要先確認目標 database 存在：

```sql
SHOW DATABASES LIKE 'archive_db';
```

也要確認目標表名沒有被使用：

```sql
SHOW TABLES FROM archive_db LIKE 'employee';
```

如果目標 database 不存在，或目標表名已存在，會失敗。

### 5.2.5 跨 database 移表的限制

把表移到另一個 database 時，要特別小心這幾點：

1. 如果表有 Trigger，不能直接把表 rename 到另一個 database，否則可能出現 trigger schema 不一致錯誤。
2. View 可以用 `RENAME TABLE` 改名，但不能用這種方式把 View 移到不同 database。
3. 如果跨不同檔案系統移動表，成功與否可能受作業系統底層檔案移動能力影響。
4. 如果有外鍵關係，雖然 MySQL 會處理部分外鍵 metadata，但正式環境仍建議先完整檢查。
5. 如果有表級權限授予舊表名，改名後不會自動搬到新表名。

所以跨 database rename 不應該當成「很輕鬆的搬家操作」。

正式環境建議至少確認：

```sql
-- 是否有 trigger
SELECT TRIGGER_NAME
FROM INFORMATION_SCHEMA.TRIGGERS
WHERE TRIGGER_SCHEMA = 'current_db'
  AND EVENT_OBJECT_TABLE = 'employee';

-- 是否有外鍵關係
SELECT TABLE_SCHEMA, TABLE_NAME, CONSTRAINT_NAME, REFERENCED_TABLE_SCHEMA, REFERENCED_TABLE_NAME
FROM INFORMATION_SCHEMA.KEY_COLUMN_USAGE
WHERE (TABLE_SCHEMA = 'current_db' AND TABLE_NAME = 'employee')
   OR (REFERENCED_TABLE_SCHEMA = 'current_db' AND REFERENCED_TABLE_NAME = 'employee');
```

## 5.3 使用 `ALTER TABLE ... RENAME` 重命名表

除了 `RENAME TABLE`，也可以使用 `ALTER TABLE` 改表名。

語法：

```sql
ALTER TABLE old_table_name RENAME TO new_table_name;
```

也可以寫成：

```sql
ALTER TABLE old_table_name RENAME AS new_table_name;
```

或：

```sql
ALTER TABLE old_table_name RENAME new_table_name;
```

例如：

```sql
ALTER TABLE dept RENAME TO department;
```

這和下面這句在概念上等價：

```sql
RENAME TABLE dept TO department;
```

### 5.3.1 `ALTER TABLE ... RENAME` 適合什麼情境？

`ALTER TABLE ... RENAME` 適合：

- 只改一張表名；
- 你已經在使用 `ALTER TABLE` 調整表結構；
- 希望語法集中在 `ALTER TABLE` 這個章節學習；
- 要處理 `TEMPORARY` table 改名。

例如：

```sql
ALTER TABLE employee RENAME TO employee_archive;
```

### 5.3.2 可以和其他 `ALTER TABLE` 操作放在一起嗎？

MySQL 的 `ALTER TABLE` 語法允許在同一條語句中放多個 `alter_option`。

例如理論上可以把改名和新增欄位放在同一條 SQL：

```sql
ALTER TABLE employee_old
    RENAME TO employee,
    ADD COLUMN updated_at DATETIME NULL COMMENT '更新時間';
```

但是實務上，我通常建議你不要在正式環境一開始就這樣寫。

更安全、可讀性更高的做法是拆開：

```sql
ALTER TABLE employee_old RENAME TO employee;

ALTER TABLE employee
    ADD COLUMN updated_at DATETIME NULL COMMENT '更新時間';
```

原因是：

- 出問題時比較容易判斷是哪一步出錯；
- migration 腳本比較清楚；
- rollback / revert 腳本比較好寫；
- 上線審查時比較容易看懂；
- 改名和改結構的風險不同，不一定要綁在一起。

學語法時可以知道它能合併；正式環境則應該優先選擇可讀、可審查、可回復的寫法。

## 5.4 表重命名後哪些東西會受影響？

改表名不會改表內資料，但會影響所有「用表名找表」的地方。

### 5.4.1 程式碼中的 SQL

例如原本 Java Mapper XML：

```xml
<select id="findAll" resultType="Employee">
    SELECT id, name, hired_at
    FROM emp
</select>
```

表名從 `emp` 改成 `employee` 後，這段 SQL 必須跟著改：

```xml
<select id="findAll" resultType="Employee">
    SELECT id, name, hired_at
    FROM employee
</select>
```

否則程式會查不到表。

### 5.4.2 View

如果 View 裡面使用了舊表名，改表名後 View 可能失效。

檢查方式：

```sql
SELECT TABLE_NAME
FROM INFORMATION_SCHEMA.VIEWS
WHERE TABLE_SCHEMA = DATABASE()
  AND VIEW_DEFINITION LIKE '%emp%';
```

如果找到相關 View，要檢查：

```sql
SHOW CREATE VIEW view_name;
```

然後根據新表名重新建立或修改 View。

### 5.4.3 Stored Procedure / Function

如果 Stored Procedure 裡面寫死舊表名，也要一起調整。

檢查方式：

```sql
SELECT ROUTINE_NAME, ROUTINE_TYPE
FROM INFORMATION_SCHEMA.ROUTINES
WHERE ROUTINE_SCHEMA = DATABASE()
  AND ROUTINE_DEFINITION LIKE '%emp%';
```

找到後用：

```sql
SHOW CREATE PROCEDURE procedure_name;
SHOW CREATE FUNCTION function_name;
```

確認完整內容。

### 5.4.4 Trigger

Trigger 是比較容易被忽略的地方。

檢查某張表上的 Trigger：

```sql
SELECT TRIGGER_NAME, EVENT_MANIPULATION, ACTION_TIMING
FROM INFORMATION_SCHEMA.TRIGGERS
WHERE TRIGGER_SCHEMA = DATABASE()
  AND EVENT_OBJECT_TABLE = 'emp';
```

表改名後，要確認 Trigger 是否仍符合預期。

如果要把有 Trigger 的表移到另一個 database，要特別小心，因為這類操作可能直接失敗。

### 5.4.5 Event Scheduler

如果你有排程事件，例如每天定時寫入某張表，表改名後也要更新。

檢查方式：

```sql
SELECT EVENT_NAME
FROM INFORMATION_SCHEMA.EVENTS
WHERE EVENT_SCHEMA = DATABASE()
  AND EVENT_DEFINITION LIKE '%emp%';
```

### 5.4.6 外鍵與約束名稱

表改名後，MySQL 會處理部分外鍵與檢查約束名稱。

特別是 MySQL 自動產生的名稱，例如：

```text
old_table_ibfk_1
old_table_chk_1
```

改表名後，可能會反映成新表名。

但是不要因此以為所有約束命名都完全不用管。

正式環境還是建議改名前後都看一次：

```sql
SHOW CREATE TABLE old_table;
-- 改名後
SHOW CREATE TABLE new_table;
```

特別注意：

- 外鍵名稱是否符合團隊規範；
- 外鍵是否仍正常；
- `CHECK` constraint 名稱是否符合預期；
- 是否有命名衝突導致改名失敗。

### 5.4.7 表級權限

這點很重要：

> 針對舊表名授予的表級權限，不會自動搬到新表名。

例如以前可能有：

```sql
GRANT SELECT ON app_db.old_table TO 'report_user'@'%';
```

表名改成 `new_table` 後，要重新確認授權：

```sql
SHOW GRANTS FOR 'report_user'@'%';
```

必要時補上：

```sql
GRANT SELECT ON app_db.new_table TO 'report_user'@'%';
```

並視情況回收舊權限。

## 5.5 正式環境重命名表的建議流程

正式環境不要直接看到需求就執行：

```sql
RENAME TABLE old_table TO new_table;
```

比較安全的流程如下。

### 5.5.1 第一步：確認改名理由

先確認為什麼要改表名：

- 原命名不符合業務語意？
- 命名規範要統一？
- 系統重構？
- 舊表和新表要切換？
- 要把表移到 archive database？
- 是否真的需要改名，而不是建立 View 或調整程式命名？

如果只是 Java Entity 想換名字，不一定非要改資料庫表名。

例如可以用 ORM 映射：

```java
@TableName("old_table")
public class Employee {
    // ...
}
```

資料庫表名是系統邊界的一部分，改名會影響面比普通 class rename 大很多。

### 5.5.2 第二步：盤點依賴

至少要盤點：

- 後端 SQL；
- 前端是否間接依賴欄位或報表名稱；
- Mapper XML；
- DAO / Repository；
- View；
- Stored Procedure / Function；
- Trigger；
- Event；
- 批次程式；
- 報表；
- 外部系統資料同步；
- 資料庫權限；
- 備份與監控腳本。

程式碼可以用搜尋：

```bash
# Linux / macOS / Git Bash
grep -R "old_table" ./src ./sql ./mapper
```

如果在 Windows，也可以用 IDE 的全域搜尋。

### 5.5.3 第三步：準備 migration SQL

範例：

```sql
-- 1. 改名前檢查
SELECT DATABASE();
SHOW TABLES LIKE 'old_table';
SHOW TABLES LIKE 'new_table';
SHOW CREATE TABLE old_table;

-- 2. 正式改名
RENAME TABLE old_table TO new_table;

-- 3. 改名後檢查
SHOW TABLES LIKE 'old_table';
SHOW TABLES LIKE 'new_table';
SHOW CREATE TABLE new_table;
SELECT COUNT(*) FROM new_table;
```

### 5.5.4 第四步：準備反向 SQL

雖然 `ROLLBACK` 不可靠，但你可以準備明確的反向 SQL。

例如：

```sql
RENAME TABLE new_table TO old_table;
```

如果是多表改名，也要準備完整反向版本：

```sql
-- 正向
RENAME TABLE
    old_user TO app_user,
    old_order TO app_order;

-- 反向
RENAME TABLE
    app_user TO old_user,
    app_order TO old_order;
```

如果涉及程式版本、View、權限、排程、外部系統，反向流程也要一起準備，不能只準備一條 SQL。

### 5.5.5 第五步：先在測試環境演練

在測試環境確認：

- migration SQL 可以成功；
- 反向 SQL 可以成功；
- 應用程式可以正常啟動；
- 核心查詢可以正常運作；
- 報表可以正常產生；
- 批次程式可以正常跑；
- 權限沒有問題；
- View / Procedure / Trigger / Event 沒有失效。

### 5.5.6 第六步：正式環境低峰時段執行

雖然改表名通常比改欄位型別輕很多，但仍可能涉及 metadata lock。

正式環境建議：

- 選低峰時段；
- 先確認沒有長交易卡住；
- 執行前通知相關人員；
- 執行後立刻跑 smoke test；
- 保留操作紀錄；
- 如果失敗，按預先準備的處理流程回復。

## 5.6 常見場景範例

### 5.6.1 把教材表名改成正式語意表名

原本：

```sql
CREATE TABLE emp (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(50) NOT NULL
);
```

改成更清楚的名稱：

```sql
RENAME TABLE emp TO employee;
```

### 5.6.2 統一表名前綴

原本：

```text
user
order
order_item
```

想改成：

```text
app_user
app_order
app_order_item
```

可以：

```sql
RENAME TABLE
    user TO app_user,
    `order` TO app_order,
    order_item TO app_order_item;
```

注意：`order` 是容易和 SQL 關鍵字混淆的名稱，實務上不建議直接拿來當表名；如果已經存在，要用反引號包起來。

### 5.6.3 新舊表切換

假設你已經準備好一張新表：

```text
product_new
```

原正式表是：

```text
product
```

想切換成：

```text
product      -> product_old
product_new  -> product
```

可以：

```sql
RENAME TABLE
    product TO product_old,
    product_new TO product;
```

這種方式常見於資料重建、資料校正、離線建表後快速切換。

但要注意：

- `product_new` 的欄位、索引、約束是否和程式期待一致；
- 資料是否完整；
- 外鍵是否需要調整；
- 權限是否需要補；
- 是否有 View / Procedure / Trigger 依賴原表。

### 5.6.4 將表移到備份 database

例如把舊表移到 `archive_db`：

```sql
RENAME TABLE app_db.login_log TO archive_db.login_log_2025;
```

這種做法要特別注意：

- `archive_db` 是否存在；
- 表是否有 Trigger；
- 是否有外鍵；
- 是否有權限問題；
- 是否有跨檔案系統風險；
- 程式是否還會查原本的 `app_db.login_log`。

## 5.7 常見錯誤與修正

### 錯誤 1：新表名已存在

```sql
RENAME TABLE emp TO employee;
```

如果 `employee` 已經存在，會失敗。

改名前先查：

```sql
SHOW TABLES LIKE 'employee';
```

必要時改成其他名字，或先處理既有的 `employee`。

### 錯誤 2：忘記改程式中的 SQL

資料庫改名成功，但程式仍查舊表：

```sql
SELECT * FROM emp;
```

應改成：

```sql
SELECT * FROM employee;
```

這類錯誤通常不是資料庫問題，而是應用程式沒有同步更新。

### 錯誤 3：以為 `ROLLBACK` 可以還原表名

錯誤理解：

```sql
START TRANSACTION;
RENAME TABLE emp TO employee;
ROLLBACK;
```

正確理解：

```text
RENAME TABLE 是 DDL，會造成 implicit commit。
如果要還原，請準備明確的反向 SQL。
```

反向 SQL：

```sql
RENAME TABLE employee TO emp;
```

### 錯誤 4：跨 database 移動有 Trigger 的表

如果表有 Trigger，不要直接這樣做：

```sql
RENAME TABLE app_db.employee TO archive_db.employee;
```

應先檢查：

```sql
SELECT TRIGGER_NAME
FROM INFORMATION_SCHEMA.TRIGGERS
WHERE TRIGGER_SCHEMA = 'app_db'
  AND EVENT_OBJECT_TABLE = 'employee';
```

如果有 Trigger，要先評估是否需要刪除、重建或改成其他搬移策略。

### 錯誤 5：忘記表級權限

原本報表帳號可能只有舊表權限：

```sql
GRANT SELECT ON app_db.emp TO 'report_user'@'%';
```

改成 `employee` 後，報表帳號可能沒有新表權限。

檢查：

```sql
SHOW GRANTS FOR 'report_user'@'%';
```

補權限：

```sql
GRANT SELECT ON app_db.employee TO 'report_user'@'%';
```

## 5.8 選擇建議

### 優先使用 `RENAME TABLE` 的情況

- 只是單純改表名；
- 要一次改多張表名；
- 要交換表名；
- 要做新舊表快速切換；
- 想把語意明確寫成「rename」。

範例：

```sql
RENAME TABLE old_table TO new_table;
```

### 優先使用 `ALTER TABLE ... RENAME` 的情況

- 只處理一張表；
- 已經在 `ALTER TABLE` 語境中；
- 要改 `TEMPORARY` table；
- 需要和其他結構調整一起討論或一起執行。

範例：

```sql
ALTER TABLE old_table RENAME TO new_table;
```

### 正式環境的建議

如果是正式環境，我建議你這樣判斷：

```text
1. 只是單張小表、低風險：
   RENAME TABLE old_table TO new_table;

2. 多張表一起改名或交換名稱：
   RENAME TABLE ... 多組 TO ...

3. 臨時表改名：
   ALTER TABLE temp_old RENAME TO temp_new;

4. 同時改表名與改結構：
   可以用 ALTER TABLE，但通常建議拆成多步 migration。

5. 有大量程式、報表、View、Procedure、Trigger、Event 依賴：
   先盤點依賴，再安排版本發布與資料庫 migration。
```

## 5.9 一句話總結

```text
RENAME TABLE 是專門改表名的語法，適合純改名、多表改名與交換表名；
ALTER TABLE ... RENAME 是 ALTER TABLE 体系下的單表改名語法，適合單表或臨時表場景。
```

更重要的是：

```text
改表名不是只改資料庫，還要同步檢查所有引用舊表名的地方。
```
