# 2 創建和管理資料庫

返回章節：[第十章_创建和管理表](./README.md)

## 本節導讀

這一節正式進入「資料庫層級」的操作。

在 MySQL 裡，真正建立資料表之前，通常要先有一個資料庫作為容器。這個資料庫會承載後續的資料表、檢視、程序、函數、觸發器等物件，也會提供預設的字元集與排序規則。

可以先把整體流程想成：

```text
建立資料庫
    ↓
切換到目標資料庫
    ↓
確認目前使用的資料庫
    ↓
建立資料表
    ↓
操作表中的資料
```

這一節要掌握的不是複雜 SQL，而是幾個每天都會用到、而且出錯時很常回查的基本命令：

- 如何建立資料庫；
- 如何指定字元集與排序規則；
- 如何查看目前有哪些資料庫；
- 如何切換目前使用中的資料庫；
- 如何確認目前所在的資料庫；
- 如何修改資料庫預設字元集與排序規則；
- 如何安全理解 `DROP DATABASE` 的風險。

這一篇學完後，你要能做到：**不只是會寫 `CREATE DATABASE`，而是知道建立資料庫時哪些地方會影響後續建表與資料儲存。**

## 關鍵字

- 主題：建立資料庫、使用資料庫、修改資料庫、刪除資料庫、資料庫字元集、資料庫排序規則
- 英文：create database, create schema, show databases, use database, current database, alter database, drop database, character set, collation
- 常見搜尋：MySQL 怎麼建立資料庫、MySQL 怎麼切換資料庫、MySQL 查看目前資料庫、MySQL 修改資料庫字元集、MySQL 刪除資料庫、MySQL utf8mb4 collation
- 容易混淆：`DATABASE` vs `SCHEMA`、`CREATE DATABASE` vs `CREATE TABLE`、`SHOW DATABASES` vs `SHOW TABLES`、`CHARACTER SET` vs `COLLATE`、刪除資料庫 vs 刪除資料表

## 建議回查情境

- 開始一個新專案，需要建立新的資料庫時。
- 準備建表，但不確定目前是否已經切換到正確資料庫時。
- SQL 執行出現 `No database selected` 時。
- 想確認資料庫實際使用的字元集與排序規則時。
- 想知道 `utf8`、`utf8mb4`、`utf8mb4_0900_ai_ci` 差在哪裡時。
- 想刪除測試資料庫，但怕誤刪正式資料時。

## 30 秒複習入口

- MySQL 中，`CREATE DATABASE` 和 `CREATE SCHEMA` 幾乎可以視為同義語。
- 建立新資料庫時，實務上建議明確指定 `utf8mb4`，不要只寫舊式的 `utf8`。
- `CHARACTER SET` 決定資料可以使用哪一套字元編碼；`COLLATE` 決定字串比較、排序與大小寫 / 重音敏感規則。
- 建立資料庫的常用安全寫法是：`CREATE DATABASE IF NOT EXISTS 資料庫名 ...;`。
- `USE 資料庫名;` 只會切換目前連線 session 的預設資料庫，不會影響其他連線。
- `SELECT DATABASE();` 可以確認目前預設資料庫；如果尚未選擇資料庫，結果會是 `NULL`。
- `SHOW CREATE DATABASE 資料庫名;` 可以查看資料庫實際建立資訊。
- `ALTER DATABASE` 修改的是資料庫的「預設」字元集與排序規則，通常不會自動轉換既有資料表與欄位。
- `DROP DATABASE` 會刪除整個資料庫與其中的表，屬於高風險操作。

## 速查區

### 最推薦的新建資料庫流程

MySQL 8.0 以上常見寫法：

```sql
CREATE DATABASE IF NOT EXISTS shop_db
    DEFAULT CHARACTER SET utf8mb4
    DEFAULT COLLATE utf8mb4_0900_ai_ci;

USE shop_db;

SELECT DATABASE();

SHOW CREATE DATABASE shop_db;
```

如果是 MySQL 5.7 或較舊環境，`utf8mb4_0900_ai_ci` 可能不存在，可改用該版本支援的 `utf8mb4` collation，例如：

```sql
CREATE DATABASE IF NOT EXISTS shop_db
    DEFAULT CHARACTER SET utf8mb4
    DEFAULT COLLATE utf8mb4_unicode_ci;
```

> 實務建議：不要死背某一個 collation 名稱。先知道 `utf8mb4` 是目前新專案常用方向，再依照公司 MySQL 版本與團隊規範選定 collation。

### 常用命令總表

| 目的 | 語法 |
| --- | --- |
| 建立資料庫 | `CREATE DATABASE db_name;` |
| 不存在才建立 | `CREATE DATABASE IF NOT EXISTS db_name;` |
| 建立並指定字元集 | `CREATE DATABASE db_name DEFAULT CHARACTER SET utf8mb4;` |
| 建立並指定字元集與排序規則 | `CREATE DATABASE db_name DEFAULT CHARACTER SET utf8mb4 DEFAULT COLLATE utf8mb4_0900_ai_ci;` |
| 查看資料庫 | `SHOW DATABASES;` |
| 模糊查看資料庫 | `SHOW DATABASES LIKE 'shop%';` |
| 切換資料庫 | `USE db_name;` |
| 查看目前資料庫 | `SELECT DATABASE();` |
| 查看目前資料庫的表 | `SHOW TABLES;` |
| 查看指定資料庫的表 | `SHOW TABLES FROM db_name;` |
| 查看資料庫建立資訊 | `SHOW CREATE DATABASE db_name;` |
| 修改資料庫預設字元集 / 排序規則 | `ALTER DATABASE db_name DEFAULT CHARACTER SET ... DEFAULT COLLATE ...;` |
| 刪除資料庫 | `DROP DATABASE db_name;` |
| 存在才刪除 | `DROP DATABASE IF EXISTS db_name;` |

### 高風險操作提醒

```sql
DROP DATABASE db_name;
```

這不是「清空某張表」，而是刪除整個資料庫。執行前至少確認：

```sql
SELECT DATABASE();
SHOW TABLES FROM db_name;
SHOW CREATE DATABASE db_name;
```

正式環境中，刪除資料庫前通常還要先備份，並確認自己不是連到正式機。

### 系統資料庫不要亂動

通常不要手動刪除或修改這些系統資料庫：

```text
mysql
information_schema
performance_schema
sys
```

這些資料庫與 MySQL 權限、系統資訊、效能統計、內部中繼資料有關，不是一般業務資料庫。

## 2.1 `DATABASE` 與 `SCHEMA` 的關係

在 MySQL 裡，`DATABASE` 和 `SCHEMA` 幾乎可以視為同義語。

下面兩種寫法在 MySQL 中用途相同：

```sql
CREATE DATABASE shop_db;
```

```sql
CREATE SCHEMA shop_db;
```

刪除時也一樣：

```sql
DROP DATABASE shop_db;
```

```sql
DROP SCHEMA shop_db;
```

不過在學習 MySQL 時，建議你筆記中統一使用 `DATABASE`，因為：

- 初學時比較直覺；
- MySQL 教材和可視化工具常用 `Database` 表示這一層；
- 可以避免和其他資料庫系統的 `schema` 概念混在一起。

> 補充：在 PostgreSQL、SQL Server、Oracle 等資料庫中，`schema` 的角色可能和 MySQL 不完全一樣。這一章先以 MySQL 的用法為主。

## 2.2 創建資料庫

### 2.2.1 最基本寫法

```sql
CREATE DATABASE shop_db;
```

這句話的意思是：建立一個名為 `shop_db` 的資料庫。

但是如果 `shop_db` 已經存在，這句話會報錯。因此，實務上更常使用下一種寫法。

### 2.2.2 不存在才建立

```sql
CREATE DATABASE IF NOT EXISTS shop_db;
```

這句話的意思是：

- 如果 `shop_db` 不存在，就建立它；
- 如果 `shop_db` 已存在，就不再建立，避免直接報錯。

這種寫法適合放在練習 SQL、初始化腳本、教學範例裡。

但要注意：

```sql
CREATE DATABASE IF NOT EXISTS shop_db;
```

只代表「如果不存在就建立」，**不代表已存在的 `shop_db` 一定符合你想要的字元集、排序規則或權限設計**。

所以建立後最好再確認：

```sql
SHOW CREATE DATABASE shop_db;
```

### 2.2.3 建立資料庫並指定字元集

```sql
CREATE DATABASE IF NOT EXISTS shop_db
    DEFAULT CHARACTER SET utf8mb4;
```

`CHARACTER SET` 表示這個資料庫預設使用哪一套字元編碼。

新專案通常建議使用：

```text
utf8mb4
```

原因是 `utf8mb4` 可以完整支援 Unicode，包括 emoji 和部分較少見文字。MySQL 裡早期常看到的 `utf8`，歷史上通常對應到 `utf8mb3`，只能支援最多 3 bytes 的 UTF-8 字元，不是完整的 4 bytes UTF-8。

### 2.2.4 建立資料庫並指定字元集與排序規則

```sql
CREATE DATABASE IF NOT EXISTS shop_db
    DEFAULT CHARACTER SET utf8mb4
    DEFAULT COLLATE utf8mb4_0900_ai_ci;
```

這是比較完整的寫法。

其中：

| 項目 | 作用 |
| --- | --- |
| `CHARACTER SET utf8mb4` | 決定可儲存的字元編碼 |
| `COLLATE utf8mb4_0900_ai_ci` | 決定字串比較與排序規則 |

以 `utf8mb4_0900_ai_ci` 為例，可以拆成：

| 片段 | 大致意思 |
| --- | --- |
| `utf8mb4` | 使用 utf8mb4 字元集 |
| `0900` | Unicode Collation Algorithm 9.0.0 相關規則 |
| `ai` | accent-insensitive，不區分重音 |
| `ci` | case-insensitive，不區分大小寫 |

例如在不區分大小寫的 collation 下，某些字串比較時可能會把 `A` 和 `a` 視為相等。這會影響：

- `WHERE name = 'abc'` 的比對結果；
- `ORDER BY name` 的排序結果；
- 唯一索引判斷字串是否重複的方式。

所以 collation 不是單純「語法裝飾」，而是會影響資料查詢與約束判斷。

### 2.2.5 如果沒有指定字元集與排序規則會怎樣？

如果建立資料庫時沒有指定：

```sql
CREATE DATABASE shop_db;
```

MySQL 會使用伺服器層級的預設字元集與排序規則。

你可以用下面語法查看伺服器預設值：

```sql
SHOW VARIABLES LIKE 'character_set_server';
SHOW VARIABLES LIKE 'collation_server';
```

也可以查看某個資料庫目前的預設值：

```sql
SELECT
    DEFAULT_CHARACTER_SET_NAME,
    DEFAULT_COLLATION_NAME
FROM INFORMATION_SCHEMA.SCHEMATA
WHERE SCHEMA_NAME = 'shop_db';
```

## 2.3 使用資料庫

建立資料庫後，通常要先切換到該資料庫，後續建立表或查資料才會比較方便。

### 2.3.1 查看目前有哪些資料庫

```sql
SHOW DATABASES;
```

這會列出目前帳號可看見的資料庫。

要注意：`SHOW DATABASES` 的結果和權限有關。你的帳號不一定看得到 MySQL Server 上的所有資料庫。

可以搭配 `LIKE` 做簡單篩選：

```sql
SHOW DATABASES LIKE 'shop%';
```

這會查出名稱以 `shop` 開頭的資料庫。

### 2.3.2 切換目前使用的資料庫

```sql
USE shop_db;
```

這句話的意思是：把目前連線 session 的預設資料庫切換成 `shop_db`。

之後如果你寫：

```sql
CREATE TABLE users (...);
```

MySQL 就會把 `users` 建立在目前 session 預設的 `shop_db` 中。

如果沒有先 `USE`，也可以使用完整名稱：

```sql
CREATE TABLE shop_db.users (...);

SELECT * FROM shop_db.users;
```

這種 `資料庫名.表名` 的寫法適合：

- 同一段 SQL 需要操作多個資料庫；
- 不確定目前 session 的預設資料庫；
- 寫排程、腳本、維運 SQL 時想降低誤操作風險。

### 2.3.3 查看目前正在使用哪個資料庫

```sql
SELECT DATABASE();
```

如果目前已經執行過：

```sql
USE shop_db;
```

那麼：

```sql
SELECT DATABASE();
```

會回傳：

```text
shop_db
```

如果你尚未選擇任何資料庫，`SELECT DATABASE();` 會回傳：

```text
NULL
```

這也是為什麼遇到下面錯誤時，第一件事通常是檢查目前資料庫：

```text
ERROR 1046 (3D000): No database selected
```

解法通常有兩種：

```sql
USE shop_db;
```

或在表名前加上資料庫名：

```sql
SELECT * FROM shop_db.users;
```

### 2.3.4 查看目前資料庫裡有哪些表

如果已經切換到目標資料庫：

```sql
USE shop_db;
```

可以直接查：

```sql
SHOW TABLES;
```

如果不想切換資料庫，也可以指定資料庫名稱：

```sql
SHOW TABLES FROM shop_db;
```

### 2.3.5 查看資料庫建立資訊

```sql
SHOW CREATE DATABASE shop_db;
```

更推薦在命令列或工具中使用：

```sql
SHOW CREATE DATABASE shop_db\G
```

`\G` 會讓結果垂直顯示，欄位較長時比較容易閱讀。

這個命令適合用來確認：

- 資料庫名稱是否正確；
- 字元集是否如預期；
- collation 是否如預期；
- 是否用了 `IF NOT EXISTS` 等資訊。

## 2.4 修改資料庫

### 2.4.1 修改資料庫預設字元集與排序規則

```sql
ALTER DATABASE shop_db
    DEFAULT CHARACTER SET utf8mb4
    DEFAULT COLLATE utf8mb4_0900_ai_ci;
```

這句話的意思是：修改 `shop_db` 這個資料庫的預設字元集與排序規則。

但這裡有一個很重要的觀念：

> `ALTER DATABASE` 修改的是「資料庫層級的預設值」，通常影響之後新建的表或欄位，不代表既有資料表、既有欄位和既有資料會自動全部轉換。

例如你已經有一張 `users` 表，這張表裡的 `username` 欄位原本是某個舊字元集。你執行：

```sql
ALTER DATABASE shop_db
    DEFAULT CHARACTER SET utf8mb4
    DEFAULT COLLATE utf8mb4_0900_ai_ci;
```

不代表 `users.username` 一定已經被轉成 `utf8mb4_0900_ai_ci`。

如果真的要轉換既有資料表，通常會使用表層級操作，例如：

```sql
ALTER TABLE users
    CONVERT TO CHARACTER SET utf8mb4
    COLLATE utf8mb4_0900_ai_ci;
```

但這類操作在正式環境可能會鎖表、耗時、影響索引長度或造成部署風險，所以不能隨便執行。

### 2.4.2 修改後如何確認？

可以用：

```sql
SHOW CREATE DATABASE shop_db;
```

也可以查 `INFORMATION_SCHEMA.SCHEMATA`：

```sql
SELECT
    SCHEMA_NAME,
    DEFAULT_CHARACTER_SET_NAME,
    DEFAULT_COLLATION_NAME
FROM INFORMATION_SCHEMA.SCHEMATA
WHERE SCHEMA_NAME = 'shop_db';
```

如果你想知道目前 session 的預設資料庫字元集與排序規則，可以先切換資料庫後查：

```sql
USE shop_db;

SELECT
    @@character_set_database,
    @@collation_database;
```

## 2.5 刪除資料庫

### 2.5.1 基本刪除語法

```sql
DROP DATABASE shop_db;
```

這句話會刪除 `shop_db` 這個資料庫，以及其中的所有資料表。

這是高風險操作，不建議在沒有確認的情況下直接執行。

### 2.5.2 存在才刪除

```sql
DROP DATABASE IF EXISTS shop_db;
```

`IF EXISTS` 的作用是：如果資料庫不存在，就不要因為找不到資料庫而直接報錯。

這種寫法常見於：

- 練習 SQL；
- 重建測試資料庫；
- 初始化測試環境；
- 自動化腳本。

例如：

```sql
DROP DATABASE IF EXISTS demo_db;

CREATE DATABASE demo_db
    DEFAULT CHARACTER SET utf8mb4
    DEFAULT COLLATE utf8mb4_0900_ai_ci;
```

這種寫法在練習時很方便，但在正式環境非常危險，因為它會直接刪掉整個資料庫。

### 2.5.3 刪除前檢查清單

刪除資料庫前，至少先做這些確認：

```sql
-- 1. 確認目前連線到哪個 MySQL Server
SELECT @@hostname, @@port;

-- 2. 確認目前預設資料庫
SELECT DATABASE();

-- 3. 確認目標資料庫是否存在
SHOW DATABASES LIKE 'shop_db';

-- 4. 確認目標資料庫有哪些表
SHOW TABLES FROM shop_db;

-- 5. 確認資料庫建立資訊
SHOW CREATE DATABASE shop_db;
```

如果是正式資料庫，還要確認：

- 是否已經備份；
- 是否經過主管或 DBA 確認；
- 是否在維護時間內；
- 是否確認不是正式機或正式庫；
- 是否確認應用程式已停止寫入。

### 2.5.4 刪除目前使用中的資料庫會怎樣？

如果你目前使用的是：

```sql
USE shop_db;
```

然後執行：

```sql
DROP DATABASE shop_db;
```

資料庫被刪除後，目前 session 的預設資料庫會被清掉。

這時再執行：

```sql
SELECT DATABASE();
```

可能會得到：

```text
NULL
```

所以刪除資料庫後，如果要繼續操作其他資料庫，需要重新：

```sql
USE other_db;
```

## 2.6 最小完整練習流程

你可以用下面這段作為本節的完整練習：

```sql
-- 1. 建立資料庫
CREATE DATABASE IF NOT EXISTS demo_shop
    DEFAULT CHARACTER SET utf8mb4
    DEFAULT COLLATE utf8mb4_0900_ai_ci;

-- 2. 查看資料庫是否存在
SHOW DATABASES LIKE 'demo_shop';

-- 3. 查看資料庫建立資訊
SHOW CREATE DATABASE demo_shop;

-- 4. 切換資料庫
USE demo_shop;

-- 5. 確認目前資料庫
SELECT DATABASE();

-- 6. 查看目前資料庫有哪些表
SHOW TABLES;

-- 7. 建立一張最簡單的測試表
CREATE TABLE users (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    username VARCHAR(50) NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 8. 再次查看資料表
SHOW TABLES;

-- 9. 查看表結構
DESC users;

-- 10. 練習完後刪除測試資料庫
-- 注意：這會刪除 demo_shop 裡的所有表
DROP DATABASE IF EXISTS demo_shop;
```

如果你的 MySQL 版本不支援 `utf8mb4_0900_ai_ci`，把 collation 改成公司或版本支援的 `utf8mb4` collation。

## 2.7 常見錯誤與排查

| 錯誤 / 現象 | 常見原因 | 排查或解法 |
| --- | --- | --- |
| `Can't create database ... database exists` | 資料庫已存在 | 使用 `CREATE DATABASE IF NOT EXISTS`，或先確認是否真的要重建 |
| `Unknown database 'xxx'` | 資料庫不存在或名稱打錯 | `SHOW DATABASES LIKE 'xxx';`，確認後再 `CREATE DATABASE` |
| `No database selected` | 尚未 `USE` 任何資料庫 | 執行 `USE db_name;`，或使用 `db_name.table_name` |
| `Access denied` | 權限不足 | 請 DBA 或管理者確認帳號是否有 `CREATE`、`DROP`、`ALTER` 等權限 |
| `Unknown collation` | MySQL 版本不支援指定的 collation | 改用該版本支援的 collation，例如 MySQL 5.7 常見 `utf8mb4_unicode_ci` |
| `DROP DATABASE` 後找不到表 | 整個資料庫已被刪除 | 若是誤刪，只能依賴備份、binlog 或災難復原流程 |

## 2.8 本節該怎麼記

這一節不需要死背很多語法，重點是形成固定操作習慣。

### 建立時

```sql
CREATE DATABASE IF NOT EXISTS db_name
    DEFAULT CHARACTER SET utf8mb4
    DEFAULT COLLATE utf8mb4_0900_ai_ci;
```

記住三件事：

1. `IF NOT EXISTS` 避免資料庫已存在時直接報錯。
2. `utf8mb4` 比舊式 `utf8` 更適合新專案。
3. 建完後用 `SHOW CREATE DATABASE db_name;` 確認。

### 使用時

```sql
USE db_name;
SELECT DATABASE();
SHOW TABLES;
```

記住三件事：

1. 先 `USE`，再建表或查資料。
2. 不確定目前在哪個資料庫，就查 `SELECT DATABASE();`。
3. 腳本中可以使用 `db_name.table_name` 降低誤操作。

### 修改時

```sql
ALTER DATABASE db_name
    DEFAULT CHARACTER SET utf8mb4
    DEFAULT COLLATE utf8mb4_0900_ai_ci;
```

記住一件事：

> 它主要修改資料庫預設值，不等於把既有表與欄位全部轉換完成。

### 刪除時

```sql
DROP DATABASE IF EXISTS db_name;
```

記住一件事：

> 這會刪除整個資料庫，不只是刪除某張表，也不是只刪除表中的資料。
