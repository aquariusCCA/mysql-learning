## 本章导读

从这一章开始，我们要学习 MySQL 中非常重要的一类操作：

```text
数据处理
```

也就是对表中的资料进行：

```text
新增
修改
删除
```

对应到 SQL 语句，就是：

```sql
INSERT
UPDATE
DELETE
```

这三类语句属于 DML，也就是：

```text
Data Manipulation Language
数据操作语言
```

如果前面的章节主要是在学习：

```text
如何查询数据
```

那么这一章开始，就是学习：

```text
如何改变数据
```

这两者的风险完全不同。

查询语句 `SELECT` 写错了，通常只是查出来的结果不对，资料本身不会改变。

但是 `INSERT`、`UPDATE`、`DELETE` 写错了，就可能真的影响数据库中的资料。

例如：

```sql
UPDATE employees
SET salary = 10000;
```

如果没有写 `WHERE`，可能会把所有员工的薪资都改成 `10000`。

又例如：

```sql
DELETE FROM employees;
```

如果没有写 `WHERE`，可能会删除整张员工表中的资料。

所以本章的重点不是只学会语法，而是要建立一种安全操作数据库的思维：

> 先确认资料范围，再执行数据变更。  
> 先知道风险，再写 DML。  
> 先用 `SELECT` 检查，再使用 `UPDATE` 或 `DELETE`。  

---

## 本章学习目标

学完本章后，应能掌握：

1. 如何使用 `INSERT` 向表中插入数据。
2. 如何使用 `UPDATE` 修改表中已有数据。
3. 如何使用 `DELETE` 删除表中已有数据。
4. 如何避免忘记 `WHERE` 导致大量资料被修改或删除。
5. 如何理解 `NULL`、`DEFAULT`、`AUTO_INCREMENT` 在数据处理中的作用。
6. 如何使用多行插入提升批量新增效率。
7. 如何使用 `INSERT ... SELECT` 把查询结果插入另一张表。
8. 如何理解 `Rows matched` 和 `Changed` 的差异。
9. 如何处理外键约束导致的更新或删除失败。
10. 如何区分 `DELETE`、`TRUNCATE TABLE`、`DROP TABLE`。
11. 如何使用事务降低误修改、误删除的风险。
12. 如何理解生成列 / 计算列和 DML 的关系。

## 1. 插入数据：把新资料写入表中

第一节学习：

```sql
INSERT INTO
```

`INSERT` 的作用是：

> 向表中新增一行或多行资料。

例如：

```sql
INSERT INTO departments(department_id, department_name)
VALUES (80, 'IT');
```

这表示：

> 向 `departments` 表中新增一个部门。

学习 `INSERT` 时，要特别注意：

- 字段和值的顺序是否对应；
- 是否要指定字段名；
- 有没有主键、自增字段；
- 有没有非空字段；
- 有没有默认值；
- 是否会发生主键或唯一键重复；
- 是否需要一次插入多笔资料。

实际开发中，更推荐这种写法：

```sql
INSERT INTO departments(department_id, department_name)
VALUES (80, 'IT');
```

而不是：

```sql
INSERT INTO departments
VALUES (80, 'IT');
```

因为指定字段名的写法更清楚，也比较不容易受到表结构变化影响。

---

## 2. 更新数据：修改已经存在的资料

第二节学习：

```sql
UPDATE
```

`UPDATE` 的作用是：

> 修改表中已经存在的资料。

例如：

```sql
UPDATE employees
SET department_id = 70
WHERE employee_id = 113;
```

这表示：

> 找到员工编号为 `113` 的员工，  
> 把他的部门编号改成 `70`。

学习 `UPDATE` 时，最重要的是理解：

```text
SET 决定改什么
WHERE 决定改谁
```

例如：

```sql
UPDATE employees
SET salary = salary * 1.1
WHERE department_id = 90;
```

这表示：

> 把 `90` 部门所有员工的薪资增加 10%。

如果少了 `WHERE`：

```sql
UPDATE employees
SET salary = salary * 1.1;
```

就可能变成：

> 把所有员工的薪资都增加 10%。

所以 `UPDATE` 的安全重点是：

```text
先 SELECT 检查范围，再 UPDATE 修改资料。
```

---

## 3. 删除数据：移除已经存在的资料

第三节学习：

```sql
DELETE FROM
```

`DELETE` 的作用是：

> 从表中删除一行或多行资料。

例如：

```sql
DELETE FROM departments
WHERE department_id = 70;
```

这表示：

> 删除部门编号为 `70` 的部门资料。

学习 `DELETE` 时，最重要的是理解：

```text
DELETE 删除的是资料，不是表结构。
```

例如：

```sql
DELETE FROM employees;
```

这会删除 `employees` 表中的所有资料，但是表本身还在。

而：

```sql
DROP TABLE employees;
```

则是把整张表删除，表结构和资料都会消失。

此外，还要分清：

| 指令 | 作用 |
|---|---|
| `DELETE FROM 表 WHERE 条件` | 删除指定资料 |
| `DELETE FROM 表` | 删除整张表中的所有资料 |
| `TRUNCATE TABLE 表` | 快速清空整张表 |
| `DROP TABLE 表` | 删除整张表结构和资料 |

删除数据时的安全重点是：

```text
先 SELECT 确认范围，再 DELETE 删除资料。
```

## 4. 生成列 / 计算列：让字段自动计算

第四节学习：

```sql
GENERATED ALWAYS AS
```

生成列也常被称为：

```text
计算列
派生列
Generated Column
Computed Column
```

它的作用是：

> 某个字段的值不需要手动插入或更新，  
> 而是根据其他字段自动计算出来。

例如：

```sql
CREATE TABLE tb1 (
    id INT,
    a INT,
    b INT,
    c INT GENERATED ALWAYS AS (a + b)
);
```

这里的 `c` 就是生成列。

插入数据时，只需要插入：

```sql
INSERT INTO tb1(id, a, b)
VALUES (1, 100, 200);
```

查询时：

```sql
SELECT id, a, b, c
FROM tb1;
```

就可以得到：

```text
id    a      b      c
1     100    200    300
```

因为：

```text
c = a + b = 100 + 200 = 300
```

生成列虽然不属于典型的 DML 语法，但它和 `INSERT`、`UPDATE` 有密切关系：

| 操作 | 和生成列的关系 |
|---|---|
| `INSERT` | 插入基础字段，生成列自动计算 |
| `UPDATE` | 更新基础字段，生成列自动变化 |
| `DELETE` | 删除整行资料时，生成列也一起消失 |

## DML、DDL、DQL 的区别

在学习本章前，需要先分清几类 SQL。

| 类型 | 全称 | 作用 | 常见语句 |
|---|---|---|---|
| DQL | Data Query Language | 查询数据 | `SELECT` |
| DML | Data Manipulation Language | 操作数据 | `INSERT`、`UPDATE`、`DELETE` |
| DDL | Data Definition Language | 定义结构 | `CREATE`、`ALTER`、`DROP`、`TRUNCATE` |
| TCL | Transaction Control Language | 控制事务 | `COMMIT`、`ROLLBACK` |

本章的主轴是 DML：

```text
INSERT
UPDATE
DELETE
```

但是也会接触一些相关内容，例如：

```sql
TRUNCATE TABLE
DROP TABLE
CREATE TABLE
ALTER TABLE
START TRANSACTION
COMMIT
ROLLBACK
```

因为实际使用数据库时，数据操作和表结构、事务控制经常会一起出现。

---

## 本章最重要的观念：DML 会改变资料

前面学习 `SELECT` 时，如果 SQL 写错，通常只是：

```text
查询结果不正确
```

但是 DML 写错，可能造成：

```text
资料真的被新增、修改或删除
```

例如：

```sql
SELECT *
FROM employees
WHERE department_id = 90;
```

这只是查询 `90` 部门的员工。

但是：

```sql
DELETE FROM employees
WHERE department_id = 90;
```

这会删除 `90` 部门的员工资料。

又例如：

```sql
SELECT *
FROM employees;
```

只是查询整张员工表。

但是：

```sql
DELETE FROM employees;
```

会删除整张员工表中的资料。

所以从这一章开始，写 SQL 时要更谨慎。

## 安全操作 DML 的基本流程

执行 `INSERT`、`UPDATE`、`DELETE` 时，可以按照下面的流程思考。

---

### 1. 先确认表结构

```sql
DESC employees;
```

确认：

- 有哪些字段；
- 字段类型是什么；
- 哪些字段不能为 `NULL`；
- 哪些字段有默认值；
- 哪些字段是主键；
- 哪些字段是外键；
- 哪些字段是自增字段。

---

### 2. 再确认目标资料

如果是 `UPDATE` 或 `DELETE`，先写：

```sql
SELECT *
FROM employees
WHERE employee_id = 113;
```

确认查出来的资料就是你要处理的资料。

---

### 3. 再执行 DML

确认无误后，才执行：

```sql
UPDATE employees
SET department_id = 70
WHERE employee_id = 113;
```

或：

```sql
DELETE FROM employees
WHERE employee_id = 113;
```

---

### 4. 最后再次确认结果

执行后，再查一次：

```sql
SELECT *
FROM employees
WHERE employee_id = 113;
```

确认资料是否真的符合预期。

---

## 推荐的安全写法

### 更新前

```sql
SELECT employee_id, last_name, department_id
FROM employees
WHERE employee_id = 113;
```

### 更新

```sql
UPDATE employees
SET department_id = 70
WHERE employee_id = 113;
```

### 更新后

```sql
SELECT employee_id, last_name, department_id
FROM employees
WHERE employee_id = 113;
```

---

## 更安全的事务写法

如果是重要资料，建议配合事务：

```sql
START TRANSACTION;

UPDATE employees
SET department_id = 70
WHERE employee_id = 113;

SELECT employee_id, last_name, department_id
FROM employees
WHERE employee_id = 113;

COMMIT;
```

如果发现改错了：

```sql
ROLLBACK;
```

也就是说：

| 指令 | 意思 |
|---|---|
| `START TRANSACTION` | 开始一组事务操作 |
| `COMMIT` | 确认提交修改 |
| `ROLLBACK` | 撤销尚未提交的修改 |

## 本章常见风险

### 风险一：忘记写 `WHERE`

危险更新：

```sql
UPDATE employees
SET department_id = 70;
```

危险删除：

```sql
DELETE FROM employees;
```

这两种写法都不是语法错误。

它们真正危险的地方是：

```text
SQL 可以正常执行，但可能影响整张表。
```

---

### 风险二：`WHERE` 条件太宽

例如：

```sql
DELETE FROM employees
WHERE last_name = 'Chen';
```

如果有很多员工都姓 `Chen`，就可能删除多笔资料。

比较安全的是使用主键：

```sql
DELETE FROM employees
WHERE employee_id = 113;
```

---

### 风险三：违反约束

例如：

```sql
UPDATE employees
SET department_id = 999
WHERE employee_id = 113;
```

如果 `departments` 表中不存在 `999` 号部门，而 `employees.department_id` 又是外键，就可能更新失败。

---

### 风险四：误以为 `TRUNCATE` 和 `DELETE` 一样

```sql
TRUNCATE TABLE employees;
```

它不是普通的删除指定资料，而是快速清空整张表。

不要把它当成：

```sql
DELETE FROM employees
WHERE 条件;
```

---

### 风险五：误以为 `DROP TABLE` 只是删除资料

```sql
DROP TABLE employees;
```

这不是删除资料而已，而是删除整张表。

表结构和资料都会消失。

---

## 本章学习建议

学习本章时，不建议只背语法。

更建议用下面的方式练习。

---

### 1. 每个 DML 都先写成 `SELECT`

例如想删除资料时，先不要急着写：

```sql
DELETE FROM employees
WHERE department_id = 90;
```

而是先写：

```sql
SELECT *
FROM employees
WHERE department_id = 90;
```

确认结果正确，再改成 `DELETE`。

---

### 2. 每次都说清楚 SQL 的意思

例如看到：

```sql
UPDATE employees
SET salary = salary * 1.1
WHERE department_id = 90;
```

不要只说：

```text
这是更新语句。
```

而是要能说出：

```text
这是把 90 部门所有员工的薪资增加 10%。
```

---

### 3. 练习判断影响范围

看到：

```sql
DELETE FROM employees
WHERE department_id = 90;
```

要立刻想到：

```text
这可能会删除多笔资料，不一定只删除一笔。
```

看到：

```sql
UPDATE employees
SET salary = 10000;
```

要立刻想到：

```text
没有 WHERE，可能更新整张表。
```

---

### 4. 注意执行结果

执行 `UPDATE` 后，可能看到：

```text
Rows matched: 1  Changed: 0
```

这不一定是错误。

它可能代表：

```text
有找到资料，但是新值和旧值一样，所以没有实际变化。
```

学习 DML 时，不只要看 SQL 有没有执行成功，也要看影响了几笔资料。

## 本章和实际开发的关系

在后端开发中，DML 几乎每天都会用到。

例如 Java 后端常见操作：

| 业务操作 | 对应 SQL |
|---|---|
| 新增用户 | `INSERT` |
| 修改用户资料 | `UPDATE` |
| 删除用户 | `DELETE` 或逻辑删除 |
| 新增订单 | `INSERT` |
| 修改订单状态 | `UPDATE` |
| 删除测试资料 | `DELETE` |
| 批量导入资料 | `INSERT ... SELECT` 或批量 `INSERT` |

在 MyBatis 中，也常看到类似方法：

```java
insertUser(user);
updateUser(user);
deleteUserById(id);
```

这些方法背后通常对应的就是：

```sql
INSERT
UPDATE
DELETE
```

所以本章内容不是单纯的 SQL 基础，而是后端开发、资料维护、报表处理、系统管理都会用到的核心能力。

## 本章和银行系统 / 企业系统的关系

在企业系统中，数据通常比程序更重要。

尤其是银行、订单、财务、客户资料这类系统，不能随便修改或删除资料。

例如：

| 资料类型 | 是否适合随便物理删除 |
|---|---|
| 客户资料 | 不适合 |
| 交易记录 | 不适合 |
| 授信资料 | 不适合 |
| 审核流程资料 | 不适合 |
| 系统测试资料 | 可以视情况删除 |
| 临时汇入资料 | 可以视情况清理 |

所以实际系统中，很多“删除”不是真的 `DELETE`，而是逻辑删除：

```sql
UPDATE users
SET deleted = 1
WHERE id = 1001;
```

或：

```sql
UPDATE orders
SET deleted_at = NOW()
WHERE order_id = 10001;
```

也就是说：

> 数据还保留在表中，只是标记为已删除。

这也是为什么学习 `DELETE` 时，不能只学语法，还要理解业务风险。

## 本章重点总结

本章要掌握的不是单独几个 SQL 语句，而是一套完整的数据处理思维。

### 1. 新增资料

```sql
INSERT INTO 表名(字段1, 字段2)
VALUES (值1, 值2);
```

重点：

```text
字段和值要一一对应。
```

---

### 2. 修改资料

```sql
UPDATE 表名
SET 字段 = 新值
WHERE 条件;
```

重点：

```text
SET 决定改什么，WHERE 决定改谁。
```

---

### 3. 删除资料

```sql
DELETE FROM 表名
WHERE 条件;
```

重点：

```text
WHERE 决定删除范围。
```

---

### 4. 自动计算字段

```sql
字段名 数据类型 GENERATED ALWAYS AS (表达式)
```

重点：

```text
生成列由数据库自动计算，不需要手动维护。
```

---

### 5. 安全操作资料

推荐流程：

```text
先 SELECT
再 DML
后确认
重要操作用事务
```

## 自测答案提示

1. DML 是数据操作语言，用来新增、修改、删除表中的数据。
2. `INSERT`、`UPDATE`、`DELETE`。
3. `SELECT` 通常只查询资料，不改变资料；`UPDATE` 会真的修改资料。
4. 因为 `WHERE` 决定影响范围，少写或写错可能影响整张表。
5. 因为可读性更高，也比较不怕表结构变化。
6. `SET` 决定要修改哪些字段，`WHERE` 决定要修改哪些资料。
7. 会删除该表中的所有资料，但表结构仍然存在。
8. `DELETE` 删除资料，`TRUNCATE` 清空表，`DROP TABLE` 删除整张表。
9. 因为 `SELECT` 可以先确认影响范围，避免误修改或误删除。
10. 重要修改、批量更新、批量删除、正式资料处理时建议使用事务。
11. `COMMIT` 是提交修改，`ROLLBACK` 是撤销尚未提交的修改。
12. 生成列是根据表达式自动计算出来的字段。
13. 插入或更新基础字段时，生成列会自动计算或重新计算。
14. 因为企业资料通常有审计、历史追踪、对账、责任归属等需求。
15. 先 SELECT，再 DML，后确认，重要操作用事务。
